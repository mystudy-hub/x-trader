## 1. 测试策略与原则

来源：规划 §9.2 首段与末段、§6.5、§6.6。

1. **预期结果独立生成**：每个验收案例保存输入数据、规则版本、事件序列和独立计算的预期账本。预期结果不得由待测算法生成；首次对照由独立手工样例确定，不能只检查两次运行彼此一致。
2. **比较口径**：数量与状态必须精确相等；金额按约定舍入单位比较，与柜台比较时明确最小金额单位和允许误差（FR-LED-04）。
3. **柜台集成用例保存依据**：同时保存脱敏后的查询或结算依据；保存目标期货公司、CTP / 柜台版本、生效区间、测试输入与脱敏结果。
4. **证据不可互相折抵**：回放 / 注入不能折抵实时运行时长，也不能证明实际滑点、成交率或容量；历史制度不能靠当前柜台行为证明。
5. **未启用不等于通过**：不在研究范围内的制度版本可标记"未启用"；已使用范围的规则或数据缺失须标记"待核验 / 失败"，不能以未启用规避。
6. **失败留痕**：每项未通过的原因、影响范围和禁用能力记录在验收报告中。
7. **不以"可导入"为架构通过条件**：依赖检查同时验证禁止边与循环依赖（NFR-03）。
8. **性能优化不改变语义**：热路径优化须通过 A06、A07、A15 验证（NFR-02）。

## 3. 证据分类

来源：规划 §9.2 末段、§6.5 第 4 项、§6.6 末条。

| 证据类型 | 能证明 | 不能证明 |
| :--- | :--- | :--- |
| 实时观测 | 在真实行情与真实柜台下的实际行为、实际滑点、成交率、耗时；运行时长 | 未自然发生的场景；更大规模订单的冲击与容量 |
| 历史回放 | 时序、订单、账本逻辑在固定输入下的正确性；历史制度边界（须配原公告与固定版本） | 实时运行时长；真实滑点与成交率；当前柜台能力 |
| 故障注入 | 恢复协议、去重、预占保留、门禁行为在指定故障下的正确性 | 真实故障的发生方式与频率；运行时长 |
| 柜台实测 | 当前柜台的开平映射、报撤权限、查询口径、认证顺序等能力 | 历史制度；其他柜台或版本；真实市场成交假设 |

每项场景证据逐项标记类型，保存事件时间、输入数据、日历及规则版本、回放或注入配置与结果。已用回放覆盖但未在真实市场观察的场景仍须在校准报告中列明。

## 8. 可复现性与回放一致性检查

来源：规划 §5.5、§6.6、A15、A28。

1. **固定输入**：run_manifest 锁定数据哈希、代码哈希（含未提交改动）、依赖锁文件、规则与日历版本、执行策略与数据源、撮合参数、随机种子、同时间事件优先级、数据排序规则、时间范围、样本划分。清单不包含账户凭证。
2. **重跑一致**：同一环境、输入和随机种子下，订单、成交、账本规范化哈希一致；跨平台数值差异采用事先声明的容差并保留环境信息。
3. **跨倍速一致**：单步、原速、加速、尽快运行得到相同规范订单、成交、预占及账本；倍速只控制墙钟播放速度，不改变事件时间、可见时间和同时间事件顺序，不以墙钟 `sleep` 决定业务结果。
4. **首次对照独立**：首次对照由独立手工样例确定，之后的回归以该基线为准；不能只检查两次运行彼此一致。
5. **新版本不改旧快照**：数据补录、规则修订、代码或配置变更生成新实验标识；发布新版本不改变旧快照内容；硬链接只用于受不可变管理的源文件。
6. **回放隔离**：回放强制绑定 `SimulatedGateway` 与隔离状态存储，不加载实盘凭证或向真实交易端口发送请求；回放证据不混入实盘统计。
7. **性能优化回归**：任何热路径优化后重跑 A06、A07、A15，舍入、事件顺序与交易语义不得改变。
