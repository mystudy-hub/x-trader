本文把规划正文中散落的设计要求、硬约束和验收条件拆成带编号、可追溯的需求条目，作为后续架构设计、开发计划、测试用例和验收的唯一编号来源。读者为架构设计者、开发者、测试者及策略研究者。规划原文作为冻结来源保存；当前已确认约束以文档基线及 10 的变更记录为准，未被已确认变更覆盖的约束继续遵守原规划。本文不新增任何交易所或柜台事实，规划中"须核验 / 不能作为默认"的内容在本文保持同样的措辞。

## 1. 拆解方法与编号规则

### 1.1 编号规则

- 功能需求：`FR-<域>-<两位序号>`，域包括 SCOPE、DATA、CAL、CON、ORD、LED、RULE、RISK、REC、MATCH、EXEC、VAL、OPS、LIVE。
- 非功能需求：`NFR-<两位序号>`。
- 评审补充需求：使用稳定 FR 编号并关联 PROP 议题，标注【评审补充】、状态为“待确认”；不进入正式阶段出口。确认后保留编号，在 10 记录变更并补齐来源、阶段和验收。
- 验收案例编号沿用规划 §9.2：A01–A29，A25 子用例 A25-01–A25-07。
- 来源引用格式：`规划 §4.1.2`；表示规划第四章 4.1 节第 2 小节。

### 1.2 优先级定义

| 优先级 | 含义 |
| :--- | :--- |
| P0 | 对应阶段及适用范围的必需项；缺失其应交付部分则该阶段不能验收。M3、M4、M6 分别是工程闭环、研究交付、实盘校准，不合并成一次首版交付。 |
| P1 | 非出口阻塞的后续优化；不能用此标签推迟既定硬约束或验收要求。 |
| P2 | 按策略类别、订单/保证金能力或范围扩展启用；一旦启用，其适用规则与验收即为必需。 |

### 1.3 阶段编号

阶段编号与规划 §9.1 一一对应：

| 阶段 | 规划名称 |
| :--- | :--- |
| S0 | 策略类别、接口与数据核验 |
| S1 | 数据契约、规则、日历与持久化（精简版） |
| S2 | 共享交易领域内核 |
| S3 | 单品种简化 Bar 回测与快速研究通道 |
| S4 | 多品种、移仓与节前处理 |
| S5 | CTP 仿真、恢复与看门狗联调 |
| S6 | 影子模式与最小手数实盘 |
| S7 | 扩大范围与精细撮合 |

需求按能力子项列出阶段：领域协议、端到端回测、当前柜台联调与精细撮合可在不同阶段交付。03、06 与本表使用 requirements.json 的同一份阶段数据；实现可以提前开展，但不能据此后移或跳过应通过的阶段出口。

### 1.4 条目格式

```
### FR-XXX-NN 标题
- 优先级 / 阶段 / 来源 / 验收（由 requirements.json 生成）
- 原始需求 / 适用范围（由 requirements.json 生成）
- 描述：1–3 句
- 硬约束：规划中"不得 / 不能 / 禁止 / 必须"的要点逐条列出
- 备注：依赖、待核验项（可选）
```

## 2. 功能需求

### 2.1 SCOPE 范围

### FR-SCOPE-01 首版范围

- 优先级：P0  阶段：S0（适用部分）  来源：规划 §一、§1.1  验收：G-SCOPE
- 原始需求：R-01、R-13；适用范围：首版配置、所选策略类别及每次范围扩展
- 描述：首版为 Windows、单账户、普通期货合约、面向日线 / 小时级信号的 Bar 事件驱动回测及 CLI 报告；先完成螺纹钢实际合约样例，再覆盖第二交割月及甲醇等跨交易所场景。
- 硬约束：
  - 期权、跨账户协同、组合保证金优化、GUI、遗传编程和低延迟交易不进入首版关键路径，后续按需求扩展。
  - 中金所品种只在确实要交易时加入。
  - 连续合约用于信号计算，实际合约承担成交与记账。
  - 交易所、期货公司、CTP 版本及数据供应商的具体规则须保存来源、生效时间和验证用例；未核实的能力不得作为实盘默认值。
- 备注：范围扩展规则见 FR-SCOPE-04 与规划 §9.3"范围扩展"。

### FR-SCOPE-02 策略类别声明为前置条件

- 优先级：P0  阶段：S0（适用部分）  来源：规划 §1.1  验收：G-S0
- 原始需求：R-02；适用范围：首版配置、所选策略类别及每次范围扩展
- 描述：策略类别决定数据分辨率、撮合模型、成本敏感度和验证方式，须在运行配置中声明。
- 硬约束：
  - S0 出口条件之一是在运行配置中声明目标策略类别。
  - 未声明类别的实验和账户不得进入模拟盘或实盘。
  - 类别声明写入实验清单；报告按类别列出所用撮合模型及其局限。
- 备注：首版目标类别为多品种低频 CTA。

### FR-SCOPE-03 三类策略分层要求

- 优先级：P0（低频 CTA 列）/ P2（其余两列）  阶段：S0（适用部分）  来源：规划 §1.1  验收：A12、A13、G-S0
- 原始需求：R-03；适用范围：首版配置、所选策略类别及每次范围扩展
- 描述：三类策略各自的首版必需数据与撮合、可推迟能力和必须上调优先级的事项。

| 类别 | 典型持仓周期 | 首版必需的数据与撮合 | 可推迟的能力 | 必须上调优先级的事项 |
| :--- | :--- | :--- | :--- | :--- |
| 低频 CTA（日线 / 小时级，多品种） | 数日到数月 | 实际合约信号 Bar、结算价、涨跌停价，以及执行策略所需的时段开盘或盘中价格；Bar 撮合加固定跳数滑点 | Tick 录制、盘口排队、亚秒延迟仿真 | 执行时点及其数据覆盖、移仓价差、多品种跨周期样本、长假处理 |
| 分钟级日内 | 分钟到数小时 | 实际合约 1 分钟 Bar、当日实际涨跌停价、分时段成交量；Bar 撮合加参与率 | 盘口排队估算 | 平今费率历史、成交量参与率、延迟与执行校准 |
| Tick 级 | 秒到分钟 | 原始快照录制自阶段 0 开始、Tick 撮合、基于时间的延迟事件 | 无 | 排队估算校准、影子模式、报撤限制 |

- 硬约束：
  - 分钟级日内与 Tick 级策略的能力保留设计，按 §9.1 路线在低频闭环验收后启用。
  - 信号频率与执行价格的数据粒度分别配置。

### FR-SCOPE-04 未实现规则显式禁用

- 优先级：P0  阶段：S1（适用部分）  来源：规划 §一、§9.3  验收：A19、A25、G-S1
- 原始需求：R-04；适用范围：首版配置、所选策略类别及每次范围扩展
- 描述：尚未实现或未核验的规则、能力在运行配置中明确禁用，而不是静默缺省。
- 硬约束：
  - 尚未实现的规则在运行配置中明确禁用。
  - 未知能力禁止实盘使用。
  - 每增加交易所、品种、历史研究区间、账户、订单类型、保证金模式、策略类别或数据源，须补充规则来源、适配验证及回归案例并更新 A25 适用清单；既有样例通过不能自动证明新增范围正确。

### FR-SCOPE-05 研究模式与精确核算模式

- 优先级：P0  阶段：S1（适用部分）  来源：规划 §二.3、§二.6、§4.4.2  验收：A16、A21
- 原始需求：R-05；适用范围：首版配置、所选策略类别及每次范围扩展
- 描述：系统区分研究模式（允许显式假设、在报告中标注）与精确核算模式（缺关键数据即中止）。
- 硬约束：
  - 缺少结算价、关键费率或交易时段时，精确核算模式应中止并说明缺项。
  - 研究模式可使用显式假设，并在报告中列出影响。
  - 研究模式也不能静默借用其他时段的 Open / Close 或插值补造成交价。
  - 缺失保证金规则时精确核算模式中止；研究模式按 FR-RULE-05 的默认假设。
  - 进入模拟盘前必须以能力表和期货公司实际费率替换研究假设。

### FR-SCOPE-06【评审补充】首版最小闭环定义

- 优先级：待确认  阶段：待确认（建议 S3）  来源：评审补充（PROP-01，待确认）  验收：待定
- 原始需求：—；适用范围：待确认议题，不进入正式阶段出口
- 描述：PROP-01 建议在 S3 内增加 S3a 最小闭环（一个实际合约、日线信号、固定连续交易时刻的 1 分钟 Bar 开盘执行、显式成本、两种盈亏视图及约 20 笔独立手工账），供内部迭代；S3b 完成原 S3 的全部出口。
- 边界：S3a 不等于 S3 验收通过，其初步结果不用于模拟盘或实盘准入；不把既定 A05、A16、A17、A19、A20、A25、A28 等验收后移到 S4。
- 状态：待确认；默认继续按原 S3 完整出口执行。

### 2.2 DATA 数据

### FR-DATA-01 通用标识与时间字段

- 优先级：P0  阶段：S1（适用部分）  来源：规划 §5.2.1  验收：A16、A29
- 原始需求：R-78；适用范围：已启用数据集、信号与执行价格范围；Tick 部分随能力启用
- 描述：所有行情与派生数据集共用一组标识、时间与质量字段。

| 字段 | 类型及语义 |
| :--- | :--- |
| `instrument_id`、`symbol`、`exchange` | 稳定的实际合约标识、原始柜台代码、交易所；完整交割年月放在合约目录中，连续序列另有类型标识。 |
| `event_time` | 事件实际发生时间，统一存储为带 UTC 时区的时间戳，展示及交易日历计算使用 `Asia/Shanghai`。 |
| `receive_time` | 本地实际收到实时消息的时间；历史文件无此信息时为空。 |
| `available_at` | 回测中允许策略获知该记录的最早时间，来自历史发布时间或有明确标识的发布 / 传输延迟假设。 |
| `trading_day`、`session_id` | 结算交易日使用 DATE；时段标识用于跨夜盘、竞价、休市及特殊交易日处理。 |
| `source_id`、`source_seq`、`ingest_seq` | 来源及其序号（若提供）、本地采集序号；序号作用域及连接重置规则需定义。 |
| `ingested_at`、`schema_version`、`quality_flags` | 本次导入时间、结构版本及质量标记。 |

- 硬约束：
  - `receive_time` 在历史文件中不能伪造为实测接收时间。
  - 导入时间不等于历史可获知时间。
  - 逻辑 Schema 必须完整可恢复；时间戳精度不能超过来源实际提供的精度。
  - 文件路径使用安全编码后的标识。

### FR-DATA-02 各数据集定义

- 优先级：P0（基础/已启用数据集）/ P2（Tick）  阶段：S1（基础数据集与契约） / S4（主力映射/连续因子数据集） / S5（InstrumentStatus 与账户查询视图） / S7（Tick 数据集）  来源：规划 §5.2.2  验收：A16、A21、A25、A26
- 原始需求：R-79；适用范围：已启用数据集、信号与执行价格范围；Tick 部分随能力启用

| 数据集 | 必需字段与处理规则 |
| :--- | :--- |
| Bar | `bar_start`、`bar_end`、`interval`、`open/high/low/close`、本周期 `volume` / `turnover`、期末 `open_interest`。明确区间边界、覆盖时段、Open 所属时刻、竞价归属及可见时间。 |
| ExecutionReference（派生视图） | 实际合约、目标 `session_id`、`reference_time`、`price_type`、参考价格、源记录标识、来源版本与分辨率、可见时间及质量标记。仅从确实覆盖所选执行时点的原始数据生成，区分夜盘开盘、日盘开盘、下一 Bar 开盘及固定盘中时刻。 |
| Tick / L1 快照 | `last_price`、`bid_price_1/ask_price_1`、`bid_volume_1/ask_volume_1`、交易日累计成交量和成交额、持仓量、`pre_settlement_price`、实际 `upper_limit_price/lower_limit_price`、交易状态。 |
| Settlement | 实际合约、交易日、官方 `settlement_price`、前结算价、`published_at`、可见时间、临时 / 最终状态、修订版本及来源；结算修订作为新记录发布。 |
| Instruments | 原始代码及别名、完整交割年月、上市 / 到期及最后交易日、乘数、最小价格变动、账户最晚平仓限制、常规夜盘能力及其生效版本；关联短代码解析依据与历史合约目录。 |
| Sessions | 实际合约、`session_id`、`trading_day`、带时区的起止时刻、`phase`、报单 / 撤单 / 撮合权限、权限受理层级、竞价类型及规则引用、订单延续规则、该交易日是否实际有夜盘；关联日历版本、常规模板、例外公告、来源及适用柜台能力版本。 |
| InstrumentStatus | 实际合约、原始状态、规范交易阶段、来源及接收时间、有效范围与质量标记；保留与日历冲突的证据。 |
| DominantMapping / ContinuousFactors | 决策与生效时间、输入版本、映射合约、调整参考价与因子、收益率视图的两端合约和时刻。 |
| AccountSnapshot | 账户、查询批次、所属交易日、结算版本、事件游标、一致性状态及资金 / 持仓视图；原始半结算结果与最后一致快照分开保存。 |

- 硬约束：
  - 未完成 Bar 不按最终 OHLC 发布。
  - ExecutionReference 的成交量若来源未提供则为空，不借用整日成交量冒充该时刻可用量。
  - Sessions 起止区间按左闭右开解释；同一合约及时点的阶段与权限须唯一；正常休市显式表示；规则缺口或冲突标记为未知，不能静默补成连续交易；只撤不报窗口必须可独立表达；品种通常有夜盘不能替代该交易日的实际时段记录。
  - InstrumentStatus 不能用过期状态放行请求。
  - DominantMapping 用于信号的所有输入满足当时可见性。
  - AccountSnapshot 不混入行情 Parquet。
  - 规范目录按 `bar/1m`、`bar/5m`、`bar/1h`、`bar/1d`、`execution_reference`、`tick`、`settlement` 分层，按实际合约、交易日或月份分区并保存版本；派生视图保留源数据及日历版本，不改变源记录的可见时间。
  - 涨跌停控制优先使用对应交易日的实际价格边界；由比例推导时需按交易所舍入及特殊调整规则核验。

### FR-DATA-03 available_at 可见性

- 优先级：P0  阶段：S1（适用部分）  来源：规划 §3.4、§5.3、§5.4.2  验收：A11、A16、A17
- 原始需求：R-21；适用范围：已启用数据集、信号与执行价格范围；Tick 部分随能力启用
- 描述：策略与风控只能读取当时可见的数据和规则版本。
- 硬约束：
  - 策略只能查询 `available_at <= 当前策略时钟` 的数据，禁止通过直接读取数据湖获得未来信息。
  - 跨品种和基本面联表必须明确合约键、交易日、实际时刻及 `available_at` 条件；发布时间较晚的数据不能回填到较早的策略决策中。
  - 晚发布的费用或结算更正按更正事件入账，不能提前提供给策略；历史发布时间不可考时，明确标记时间假设及其回测限制。

### FR-DATA-04 分段录制与原子发布

- 优先级：P0（历史 Bar 发布）/ P2（实时 Tick 录制）  阶段：S1（历史 Bar 原子发布） / S7（实时 Tick 录制，提前启用须提前验收）  来源：规划 §5.1  验收：A14
- 原始需求：R-19、R-76；适用范围：历史 Bar 发布必需；实时 Tick 录制按实际启用范围验收，低频路线可推迟到 S7
- 描述：实时行情经独立有界队列写入短周期完整分段，校验后原子重命名并登记 manifest。
- 硬约束：
  - 标准 Feather / Arrow IPC 文件不承担可任意追加、断电后自动恢复的 WAL 承诺。
  - 分段周期只是配置项，不能直接推导最大数据损失时间。
  - 发布前的临时文件对读者不可见；崩溃后隔离未完成文件；完整文件已重命名但清单未提交时，恢复程序校验后补登记；清单只引用已完成且校验通过的文件。
  - 使用目标平台持久化接口，并测试进程崩溃、断电恢复及磁盘满；按实测定义 RPO。
  - 本地序号不能证明交易所到本地的链路从未丢包；断线和来源缺口需单独标记。
  - 队列积压或写入失败必须计数并告警；超过数据质量容忍度时禁止新增风险；录制故障不能静默丢弃数据，也不能阻塞订单回报处理队列。

### FR-CAL-07 MarketPhase 与操作权限

- 优先级：P0  阶段：S1（解析） / S3（撮合）  来源：规划 §4.2 交易小节  验收：A25、A25-01、A25-02、A25-04

- 描述：`MarketPhase` 按实际合约维护竞价申报、竞价撮合、只撤不报、等待连续交易、连续交易、小节休市、停牌、收盘及未知状态；每个阶段分别配置 `can_submit()`、`can_cancel()`、`can_match()`。
- 硬约束：
  - 阶段与 `session_id` 分开，不为每个日夜盘小节复制一套枚举。
  - 并非所有品种都必经同一流程；不人为规定固定长度的等待阶段，不为每次小节恢复补一次竞价。

  - 区分本地保存意图、柜台预埋、交易所报单 / 撤单受理与实际撮合；休市期预埋或撤单能力须单独核验，预埋受理不等于可撮合订单，不能从"不撮合"推导所有请求都会被拒绝。

### FR-ORD-04 订单状态与回报语义

- 优先级：P0  阶段：S2（适用部分）  来源：规划 §4.1.3  验收：A02、A03
- 原始需求：R-30、R-31；适用范围：单账户已启用合约、订单类型及经核验的柜台能力

| 状态或事件 | 必须执行的处理 |
| :--- | :--- |
| `CREATED / SUBMITTING` | 提交前持久化意图与预占，分配稳定的 `client_order_id`，保存父子订单关系。 |
| `ACCEPTED / PARTIALLY_FILLED` | 保存柜台订单标识与累计成交信息，按唯一成交记账，不依靠回调到达顺序推断全部事实。 |
| `FILLED / CANCELED / REJECTED / EXPIRED` | 已确认终态；迟到状态不能使订单倒退，迟到但尚未入账的真实成交仍需处理。 |
| `cancel_pending` | 独立撤单状态，可与部分成交并存。撤单拒绝后原委托可能仍有效，预占继续保留。 |
| `UNKNOWN` | 发送、连接或恢复过程中无法确定柜台结果；保留保守预占并进入对账，不把超时自动转换为拒单。 |
| 明确未发送的本地失败 | 记录失败原因并释放相应预占；能否认定"未发送"必须由适配器的明确返回语义决定。 |

- 硬约束：
  - 网关须覆盖本地调用返回、`OnRspOrderInsert`、`OnErrRtnOrderInsert`、`OnRtnOrder`、`OnRtnTrade` 及撤单错误回报，转换成统一领域事件。
  - 同一事实通过多种回调重复到达时，业务结果不重复计算。
  - 订单终态与累计成交事实分开维护；`CANCELED` 后仍可补记迟到成交，不因迟到的"已报"回报退回活动状态。

  - 成交先于报单回报时，优先使用已核验作用域内的 `ExchangeID + OrderSysID` 或可唯一关联的原会话订单映射绑定；`OrderRef` 不能单独作为跨会话唯一键；成交回报未携带原会话信息时不能补上当前会话号猜测关联。
  - 无法唯一归属的真实成交先持久化为待关联事件，并建立带远端标识的占位记录；确认前不猜配、不释放其他订单的预占、不发布受其影响的可交易账户快照。
  - 确认后在同一账户执行序列中一次性入账、合并占位并重建相关预占；仅策略归属未知的保留"未分配策略"标签，差异处置完成前禁止新增风险。
  - 不能因缺少本地订单或 `OrderSysID` 映射丢弃成交，也不能擅自按外部委托补开仓。
  - 迟到报单回报只合并标识、归属及预占，不再次生成成交记账；无法解释的超量或归属冲突进入对账。

### 2.6 LED 账本

### FR-LED-01 事件推导账本

- 硬约束：
  - 策略收益不包含入金、出金等外部现金流。
  - 共享一套成交与结算事实，不维护两套可各自增加余额的账本。

### FR-LED-02 计价基准与结算盈亏

- 优先级：P0  阶段：S2（适用部分）  来源：规划 §4.4.1  验收：A06、A22
- 原始需求：R-54；适用范围：已启用账户资金、费用、保证金和结算规则
- 描述：今仓初始计价基准为成交价，昨仓为上一结算价；平仓按所平持仓当前计价基准确认盈亏；日终只对剩余持仓计提到官方结算价的盈亏并更新下一交易日基准。
- 硬约束：
  - 盘中动态权益由已结余额与未实现盈亏等账户项目计算。
  - 已经划入余额的每日结算盈亏不能再次加入动态权益。

### FR-LED-03 两种盈亏视图

- 优先级：P0  阶段：S2（适用部分）  来源：规划 §4.4.1  验收：A06、A22
- 原始需求：R-55；适用范围：已启用账户资金、费用、保证金和结算规则

| 视图 | 计算基准 | 用途 |
| :--- | :--- | :--- |
| `mtm_close_pnl`（逐日盯市平仓盈亏） | 今仓按实际开仓价，昨仓按上一结算价；分别计算多空方向、乘数与对应平仓数量。 | 日常结算对账，并结合持仓盯市、费用、冻结和账户规则计算权益与风险。 |
| `trade_close_pnl`（逐笔交易平仓盈亏） | 平仓价与所匹配原始开仓批次的价格比较，跨日保留开仓成本及费用分摊。 | 扣费后的胜率、盈亏比、平均持仓时间及策略归因。 |

- 硬约束：
  - 配对规则、部分平仓与策略归属须固定。
  - 手工样例：无手续费、1 手多仓、乘数 10，100 开仓，当日结算 110，次日 108 平仓。首日结算入账 +100，次日盯市平仓 −20；逐笔平仓盈亏 +80；最终权益合计增加 80，不能再把逐笔 +80 叠加到账本。
  - 夏普、回撤、月度收益使用包含未平仓估值并剔除外部现金流的时间序列权益，不能只用已平仓交易盈亏代替。

### FR-LED-04 精度与舍入

- 优先级：P0  阶段：S2（适用部分）  来源：规划 §3.4 回测模式端口适配、§4.4.1  验收：A06、A07、A15
- 原始需求：R-24；适用范围：已启用账户资金、费用、保证金和结算规则
- 描述：报价步长内的委托 / 成交价格可用整数 Tick 表达；结算价、均价、金额和费率保留所需定点精度或使用 `Decimal`。
- 硬约束：
  - 结算价、平均价及复权指标不强制取整到报价 Tick。
  - 费用与盈亏用足够精度的定点数计算，在规定记账环节舍入到最小货币单位，避免逐项提前取整。
  - 与柜台比较时明确最小金额单位和允许误差。
  - 热路径优化须通过 A06、A07、A15 验证；性能优化不得改变舍入、事件顺序或交易语义。

### FR-LED-05 保证金与可用资金三字段

- 优先级：P0  阶段：S2（模型） / S5（口径核验）  来源：规划 §4.4.2  验收：A08
- 原始需求：R-56；适用范围：已启用账户资金、费用、保证金和结算规则
- 描述：区分持仓保证金、活动订单增量保证金、待扣费用和其他冻结；至少明确 `broker_available`、`available_for_new_trades`、`margin_coverage_equity` 三个字段。
- 硬约束：
  - 避免把柜台已包含的冻结重复扣减；模型与柜台字段的映射必须通过对账样例确认。
  - 浮盈能否参与开仓、风险度或保证金覆盖按交易所结算口径、期货公司、账户权限及生效规则核验，不能统一断言"一定能"或"一定不能"。
  - `broker_available` 附交易日、查询时点、来源与一致性状态；先核验其是否已包含浮盈浮亏、保证金及冻结。
  - `available_for_new_trades` 同时检查现有活动订单的增量需求；盈利可计入比例、浮亏扣减、汇总范围、费用与冻结的处理均版本化；不能直接把动态权益当作开仓额度。
  - `margin_coverage_equity` 注明分子与所比较保证金的定义；与开仓额度不能相加作为两笔可用资金，也不能因计入浮盈就直接减去法定保证金需求。
  - 研究模式缺少历史浮盈规则时，可显式采用"浮盈不增加开仓额度、浮亏按保守口径扣减"并做敏感性分析；已结算划入余额的盈利按新交易日规则处理，不能永久当作未实现浮盈扣除。
  - 实盘及精确核算模式以已核验账户规则和一致查询为准，差异未解释时阻止新增风险。
  - 风控同时评估现有持仓及所有活动委托可能成交后的资金需求。

### FR-RULE-02 手续费公式

- 优先级：P0  阶段：S2（适用部分）  来源：规划 §5.4.2  验收：A07
- 原始需求：R-84；适用范围：所选账户、合约、历史区间与规则版本
- 描述：`费用 = 手数 × 每手费用 + 成交价格 × 合约乘数 × 手数 × 金额费率`，再按对应规则舍入。
- 硬约束：

  - 开仓、平今、平昨费率按品种、合约、账户及生效区间分别记录；不得套用交易所统一的平今费率倍数；不得用当前费率回填历史。
  - A07 单位样例：2 手、价格 1000、乘数 10、每手 1.5 元、费率 0.0001 时合计 5 元（测试输入，非实际费率）。

### 2.8 RISK 风控

### FR-RISK-01 必经路径与串行执行序列

- 优先级：P0  阶段：S2（适用部分）  来源：规划 §4.5、§3.4  验收：A08、A09
- 原始需求：R-16、R-18、R-29、R-61；适用范围：本系统的交易命令及账户已启用范围；真实成交按事实分支处理
- 描述：风控是所有策略、移仓、看门狗及人工交易指令的必经路径；独立执行服务按账户串行执行控制权核验、风控校验和预占，网络发送在本地事务提交后进行。
- 硬约束：
  - 控制权切换与发送使用同一执行序列，避免校验通过后被旧控制者继续发单。
  - 同一账户的订单、持仓、账本与风控状态由一个执行序列更新，避免多个回调线程直接修改状态。
  - `ExecutionPort` 发送前复核控制代次。
  - 上述控制权与事前风控路径适用于交易命令；订单 / 成交事实在同一执行序列内走校验、关联、去重与入账分支，不因旧代次、既有熔断或当前资金不足而拒绝记录真实成交。未关联事实按 FR-ORD-05 处理。
  - 行情录制和分析使用独立工作队列，交易事件优先处理；队列有容量、积压指标和故障策略；订单或成交事件无法可靠保存时，禁止继续增加风险并告警。

### FR-RISK-02 三类规则与持久化计数

- 描述：交易所及监管要求、期货公司及柜台限制、内部风险偏好分别管理。
- 硬约束：
  - 撤单总数、撤单率、频繁报撤次数和持仓比例不设置无来源的生产默认值。
  - 日内回撤需明确基准、峰值更新及现金流调整方法。
  - 不同规则分别定义统计窗口、分母、重置交易日，以及由请求、接受、撤销或成交哪个事件触发计数。
  - 计数随事件持久化，重启不得清零。

- 硬约束：
  - 回测与实盘使用同一实现，在 S3 回测验收中生效，策略违规在回测报告中可见，不能推迟到模拟盘才发现。

### FR-RISK-05 熔断状态机

- 优先级：P0  阶段：S2（适用部分）  来源：规划 §4.5.3  验收：A09
- 原始需求：R-65；适用范围：本系统的交易命令及账户已启用范围；真实成交按事实分支处理
- 描述：`NORMAL -> REDUCE_ONLY -> CANCELING -> FLATTENING -> HALTED`。
- 硬约束：
  - 先禁止新增风险，再撤销冲突或增加风险的挂单；在撤单回报与迟到成交核对后按实际剩余仓位分批减仓。
  - 撤单和减仓可获得更高调度优先级并预留请求预算，但仍须遵守监管、柜台硬限制、真实可平仓量和资金检查。
  - 自身普通开仓冷却条件不应阻断合法减仓；内部限制按增加风险、撤单和降低风险分别配置；禁止为"紧急清仓"绕过全部校验。
  - 无法清仓时保留未完成状态、剩余风险、重试上限和告警；不能把发出清仓请求等同于仓位归零。
  - 进入 `HALTED` 后仍处理回报、对账和监控；恢复交易前要求异常原因消除、账户一致且风险状态明确重置。

### FR-RISK-07 唯一交易出口与控制代次

- 优先级：P0  阶段：S2（控制代次领域逻辑） / S5（唯一执行服务与最终发送校验）  来源：规划 §4.5.5  验收：A23
- 原始需求：R-17、R-67；适用范围：本系统的交易命令及账户已启用范围；真实成交按事实分支处理
- 描述：独立执行服务是本系统唯一持有该账户 CTP 交易连接的进程，持久化 `controller_id` 与单调递增的 `control_epoch`。
- 硬约束：
  - 实施单实例约束；策略、看门狗与人工控制不各自登录交易接口。
  - 对开仓、平仓 / 减仓、撤单、改单及恢复交易命令，在接收和最终发送 / 生效前校验控制权；所有发送路径均不得绕过。
  - 运行在应用进程内的止损与熔断逻辑随进程退出而失效；不能仅凭 CTP 字段或枚举推定存在交易所 / 柜台托管止损；未核验时按无托管保护设计。
  - 从备份恢复不得回退或复用已使用代次；无法确认最新控制记录时停止自动接管。

### FR-RISK-08 看门狗与接管

- 优先级：P0  阶段：S5（适用部分）  来源：规划 §4.5.5  验收：A23
- 原始需求：R-68、R-69；适用范围：本系统的交易命令及账户已启用范围；真实成交按事实分支处理
- 描述：独立监控进程检测策略心跳；超时后按配置告警等待人工，或申请接管后撤单 / 减仓。
- 硬约束：
  - 心跳超时本身不授予交易权；暂停后恢复或网络恢复的旧控制者持有过期代次，其命令必须被拒绝。
  - 接管顺序：先停发旧控制者命令，在账户执行序列内持久化新控制者及新代次，再拒绝旧代次排队命令；明确未发送的请求按失败事件释放预占；随后执行 FR-REC-04 对账，一致后才允许新控制者按配置撤单或减仓；已提交到柜台的请求不会因代次变更消失，其预占与迟到回报继续处理；接管过程写入交易事件库。
  - 执行服务重启或控制者变更时，先恢复已持久化控制记录，再推进代次；单纯 CTP 连接重连不自动切换控制者。
  - 若旧交易出口不能被确认停止或经独立机制隔离，不得仅凭心跳超时另建交易连接接管；保持禁止新增风险并告警。
  - 同机看门狗不能覆盖主机断电或整机网络失联；部署独立于交易主机的存活告警并验证人工应急路径；期货公司条件单等托管保护经能力表核验后可作为备份，不视为必定能平仓。

- 硬约束：

- 原始需求：R-73；适用范围：领域恢复协议及已启用运行模式，当前柜台部分须联调

### FR-REC-04 启动重连流程

- 优先级：P0  阶段：S2（可控网关恢复协议） / S5（柜台查询、重连与对账）  来源：规划 §4.6.2  验收：A04、A23、A26
- 原始需求：R-74；适用范围：领域恢复协议及已启用运行模式，当前柜台部分须联调
- 描述：`DISCONNECTED -> RECOVERING -> RECONCILING -> READY`；差异未解决时保持禁止新增风险。
- 硬约束：
  - 先确认执行服务单实例及旧出口隔离状态，恢复持久化控制记录；加载已提交快照与后续事件，将无法确认远端结果的请求标记为未知。
  - 按已核验的接入模式完成终端采集 / 注册、认证、登录及必要的结算确认；结合生命周期检查交易日与结算完整性；重新订阅行情；按流控查询资金、持仓、订单与成交，保留原订单标识。
  - 查询期间缓存并按序保存实时回报；订单、成交、持仓和资金查询通常不是同一原子快照，需依据完成标志、交易日、结算状态、游标和重复查询建立一致视图；避免先覆盖持仓再重放相同成交；半结算或跨交易日混合的查询不能发布为可交易快照。
  - 识别外部委托与未知发送结果，按唯一事件重建预占；查询范围不足时保持未知并提供可人工核对的记录，不推测已拒单后重发。
  - 全部一致性检查通过后才切换 `READY`；`READY` 不自动解除既有熔断或暂停状态；未解决差异、恢复超时和重复断线均须告警。

### 2.10 MATCH 撮合

### FR-MATCH-01 Bar 因果约束

- 优先级：P0  阶段：S3（适用部分）  来源：规划 §6.1  验收：A11
- 原始需求：R-88；适用范围：Bar 基础路径；Tick、排队和精细延迟按类别启用

  - 若订单在 Bar 内才生效而没有更细数据，保守模式延至下一完整 Bar 评估。
  - 无有效行情、零成交量、休市、停牌及价格边界不明时，不能补造可成交价格。
  - 默认在该 Bar 处理完成时才向策略公开本 Bar 的模拟成交结果；禁止利用完整高低价或总成交量进行同 Bar 追单和重复换手。
  - 时序因果约束不能代替防过拟合的样本外验证。

### FR-MATCH-02 订单场景与价格边界

- 优先级：P0  阶段：S3（适用部分）  来源：规划 §6.1.1  验收：A11、A12、A20、A25、A25-07
- 原始需求：R-89；适用范围：Bar 基础路径；Tick、排队和精细延迟按类别启用

| 订单场景 | 撮合条件与价格边界 |
| :--- | :--- |
| 主动成交意图 | 按柜台能力转换为支持的订单类型；仅在订单生效、时段及流动性条件满足时生成候选成交。 |
| 集合竞价、只撤窗口与小节休市 | 请求到达时按 FR-CAL-07 核验报撤权限，撮合独立检查 `can_match()`；竞价价格、数量及参与资格缺失时，不使用连续交易 Bar 冒充竞价撮合。 |
| 下一 Bar 开盘成交 | 必须在该开盘时点前已经生效，且满足竞价或连续交易规则；否则不能使用该 Bar 的开盘价。 |
| 限价买单 | `Low <= LimitPrice` 仅说明价格到达；开盘可成交时候选价可由 `Open + 滑点` 得到，但不得高于限价或超出有效价格边界。 |
| 限价卖单 | `High >= LimitPrice` 仅说明价格到达；候选价可由 `Open - 滑点` 得到，但不得低于限价或超出边界。 |
| 盘中触及限价 | 配置"触价允许候选成交"及"穿价至少一个 Tick"等情景，结合成交量预算生成部分成交，不保证触价后全部成交。 |
| 涨跌停 | 使用候选成交时点适用的实际涨跌停边界与价格 / 交易状态；开盘候选不能因随后收盘触板而被否定。 |

- 硬约束：
  - 启用竞价成交模型时，价格形成、并列价格、同价分配、有效期及未成交申报延续分别绑定适用交易所规则与可用数据；不能仅凭一所的"最大成交量"条款实现全市场竞价算法，也不能把开盘模型用于收盘竞价。
  - 首版只检查时段合法性，不要求重建竞价盘口。
  - 开盘候选与 Bar 结束时的估算分开处理；完整 Bar 的高低价、收盘状态及"一字板"分类只能在 Bar 结束时用于评估尚未成交的订单，不能改写已确定的开盘成交；仅有 OHLCV 时不推断触板与回落的盘中先后顺序。

### FR-MATCH-03 涨跌停流动性情景

- 描述：`limit_liquidity_scenario` 写入运行清单，至少提供"方向保守（默认研究假设）"与"触板无成交（压力情景）"两种。
- 硬约束：
  - 方向保守：候选时点处于涨停价时假设买单不成交，卖单仅在已观测成交量、共享参与率预算、订单生效时点及价格约束均满足时允许候选成交；跌停反向。这是缺少盘口时的保守假设，不代表市场事实。
  - 触板无成交：两方向均假设不成交，并在报告中单列。
