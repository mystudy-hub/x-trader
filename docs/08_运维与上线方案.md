## 目的与读者

本文定义 QH-Trader 从模拟盘到实盘的运维脚本职责、日常运行手册、生命周期与运维动作对照、监控与告警、日志脱敏、备份恢复、应急处置、运行环境、影子模式校准流程与上线门槛。读者为运维执行人、值守人员与项目负责人。所有时间点（如 08:55、15:30、18:30、20:55）均为示例，实际以版本化日历、柜台证据与配置为准，不得写死。

## 2. 日常运行手册

来源：规划 §4.2、§4.5 第 6 项、§8。所有触发时刻由版本化日历与配置提前量决定；不写死每天 15:30 断开、18:30 恢复或把 20:55 当作连续交易开盘。

### 2.1 开盘前检查清单

每个适用交易时段开盘前，按版本化日历与配置的提前量运行 `preopen_check.py`，逐项确认：

| 序号 | 检查项 | 通过条件 | 未通过动作 |
| :--- | :--- | :--- | :--- |
| 1 | 唯一执行服务与控制代次 | 单实例运行；持久化控制记录可读且代次单调 | 不启动交易；告警 |
| 2 | 连接与登录 | 终端采集 / 注册、认证、登录按已核验顺序完成；必要的结算确认完成 | 不进入可交易状态（A27） |
| 3 | 交易日与结算确认 | 当前交易日与日历一致；上一交易日 `SettlementReady` 已入账且账户快照一致 | 保持禁止新增风险（A26） |
| 4 | 行情时效 | 订阅合约行情年龄在阈值内 | 告警；行情过期合约禁止新增风险 |
| 5 | 规则版本 | 手续费、保证金、时段、能力表版本与配置一致，无未解决冲突 | 不发布可交易日历；告警 |
| 6 | 账户对账状态 | 上次 `reconcile.py` 无未解释差异；结算单比对通过 | 禁止新增风险直到人工确认 |
| 7 | 监控与外部告警 | 指标采集、独立存活告警通道可用 | 禁止新增风险并记录故障；通过仍可用的通道告警。撤单 / 减仓须满足控制权、连接、状态与资金检查，不能配置放行新增风险 |
| 8 | 交易阶段权限 | `MarketPhase` 与 `OnRtnInstrumentStatus` 无冲突；缺失或过期时采用保守门禁 | 保守门禁；告警 |

08:55 / 20:55 仅是部分常规时段提前五分钟的示例；节假日、取消夜盘及特殊开盘时间以日历为准。开盘时仍处于对账中的账户保持禁止新增风险并告警。

### 2.2 盘中监控

- 值守人员观察 §4 指标：行情年龄、队列积压、未知请求数量与持续时间、待关联成交、对账差异、拒单原因、过期控制命令拒绝数、报撤预算、保证金比例、未完成减仓 / 移仓。
- 每项门禁记录触发原因、时间、影响范围与解除条件。结算、对账、行情质量等临时就绪门禁在证据补齐后由同一账户执行序列重新评估并留痕；证据不完整时保持门禁。既有熔断或人工暂停不随 `READY` 自动解除，须由当前控制者通过携带有效代次的恢复命令明确重置；人工操作经 `control.py` 执行。
- 撤单 / 减仓仍须通过控制权、状态及资金检查；不可把"禁止使用半结算数据"实现成关闭风控。
- 某品种收盘不等于账户所有品种均已结束交易；按所选合约时段安排收盘任务，避免商品收盘时误停仍在交易的其他品种。

### 2.3 收盘与结算

| 事件 | 触发依据 | 运维动作 |
| :--- | :--- | :--- |
| `SessionClosed` | 按合约适用时段生成，不统一写死 15:00 | 确认该合约不再撮合；未成交订单按柜台规则处理（跨日有效或失效），不直接清空全部挂单 |
| 结算等待 | 官方结算数据尚未就绪 | 标记 `SETTLEMENT_PENDING`；不得用收盘价替代；禁止新增风险 |
| `SettlementReady` | 官方结算数据经完整性检查，带交易日及版本 | 驱动账本结算；结算修订作为差额更正事件，不覆盖旧账 |
| 结算单到达 | 期货公司结算单 | 运行 `parse_statement.py`；差异超过约定误差时禁止新增风险，直到人工确认或更正事件入账 |
| `TradingDayAdvanced` | 已确认的交易日推进 | 一次性今昨仓转换；核对待结算状态、上一交易日订单及冻结；晚到回报按原交易日处理 |
| 日终备份 | 结算与对账完成后 | 运行 `backup_state.py`，记录游标与校验 |

行情到达下一交易日但上日结算或对账未完成时，继续采集，阻止新增风险。

### 2.4 维护窗口

- 前置维护与柜台维护时间是带来源的预计窗口；按端点记录已知重启和维护窗口，不假定每个前置每天都在固定时间重启。
- 重点验证结算前后及夜盘前的恢复；定期演练重连与对账。
- Windows 更新安排在维护窗口并做重启后检查（§8）。

## 3. 生命周期状态与运维动作对照

来源：规划 §4.2"每日生命周期协调"、§4.6。运行阶段按端点及账户维护，与合约交易阶段、连接状态、风控状态分别管理，不压成一个全局状态机。

| 运行阶段 | 进入条件 | 允许的交易动作 | 运维动作 | 退出条件 |
| :--- | :--- | :--- | :--- | :--- |
| `PRE_OPEN` | 日历提前量到达 | 无新增风险 | 执行 §2.1 检查清单 | 全部检查通过 → `RUNNING`；未通过保持并告警 |
| `RUNNING` | 检查通过且一致快照已发布 | 按风控状态（NORMAL / REDUCE_ONLY 等） | 盘中监控 | 所选合约时段结束或柜台信号 → `POST_CLOSE` |
| `POST_CLOSE` | 账户所有活动合约收盘 | 撤单 / 减仓按柜台能力；不新增风险 | 等待结算数据 | 结算数据开始到达 → `SETTLEMENT_IN_PROGRESS` |
| `SETTLEMENT_IN_PROGRESS` | 结算数据到达或柜台结算开始 | 禁止新增风险 | 结算中收到的资金 / 持仓查询保存为待核对原始快照，附交易日、批次、完整性标记；不覆盖最后一致快照 | 结算单交易日与完整性核验、必要的结算确认、账户查询及增量回报核对完成 → `RECONCILING` |
| `MAINTENANCE` | 按端点规则及实际维护 / 连接证据进入；预计窗口仅用于调度检查 | 禁止新增风险 | 保持可用的回报处理、核对与告警；连接丢失同时进入独立的恢复流程 | 维护结束且满足连接恢复条件 → `RECONCILING` |
| `RECONCILING` | 结算完成或重连 | 禁止新增风险 | 运行恢复流程（05 §16）：加载快照与事件、查询、合并、差异报告 | 唯一出口、控制权、连接、行情时效、交易日、待结算状态、订单、持仓、资金全部一致 → 账户恢复状态 `READY`；生命周期按日历进入 `PRE_OPEN` 或 `RUNNING`，既有熔断 / 暂停保持；差异未解决继续告警 |

任务按账户、交易日、事件类型及版本幂等执行；重启不重复结算、转换今昨仓或重置计数；越过预计窗口仍未就绪时保持门禁并告警。登录成功或结算确认应答本身不能证明新交易日数据已完整。`READY` 不自动解除既有熔断或暂停状态。

## 4. 监控指标与告警动作映射

### 4.1 指标清单

来源：规划 §8.2，完整保留。

- 行情年龄、队列积压、写入水位、未知请求数量及持续时间、待关联成交、对账差异、预占数量、阶段权限冲突、生命周期超时、资金可用口径差异、拒单原因、过期控制命令拒绝数、报撤预算、保证金比例及未完成减仓 / 移仓。
- 数据质量：字段完整性、合约代码解析及交易日映射、事件顺序、重复记录、可见时间、价格步长和边界、盘口有效性、累计量重置、交易阶段权限、结算覆盖及规则生效区间；区分正常小节休市与行情缺失。
- 缺失字段、无成交和无效值分别表达，不将空盘口填成可交易的零价；价格有效域按实际合约、价差或复权序列类型判定，不静默修正异常数据后覆盖原件（FR-DATA-08、A16）。
- 容量：代表性订阅合约数和报单负载下的资源、吞吐、尾部延迟和恢复耗时，记录测试硬件与数据规模。研究查询和 Compaction 避免挤占交易进程资源。
- 【评审补充】待确认：本机时钟与柜台 / 交易所时间偏差；门禁错过信号数与估算成本（见 §11）。

### 4.2 告警 → 风险状态动作

来源：规划 §8.2 末条、§4.5、§5.1。

| 触发 | 告警级别 | 自动风险状态动作 | 禁止的自动动作 |
| :--- | :--- | :--- | :--- |
| 断线 | 高 | 进入 `MAINTENANCE` / `RECONCILING`；禁止新增风险；未知请求标记 `SENT_UNKNOWN` | 盲目重发；自动切换控制者 |
| 行情过期（超过阈值） | 高 | 受影响合约禁止新增风险；估值质量降级为保守估值 | 用过期最新价当作可平仓价 |
| 账本差异（对账或结算单） | 高 | 禁止新增风险直到人工确认或更正事件入账 | 自动调整账本以匹配柜台 |
| 无法持久化（交易意图、订单或成交事件；含交易库磁盘满） | 高 | 立即禁止新增风险；不发送未持久化的增加风险意图；保留未决状态，继续可安全完成的核对与告警 | 等待行情质量容忍度耗尽；记录虚假持久化成功 |
| 行情录制队列溢出 / 录制写入失败 | 中 → 高（超容忍度） | 计数告警并标记数据缺口；超过配置的数据质量容忍度时禁止新增风险 | 静默丢弃；阻塞交易回报队列 |
| 交易事件队列溢出 / 订单或成交无法可靠保存 | 高 | 立即禁止新增风险，记录未决情况并核对；不发布受影响的可交易快照 | 使用行情质量容忍度放行；丢弃真实成交；谎报保存成功 |
| 持续清仓失败（行情过期、涨跌停、限流） | 高 | 保留未完成状态、剩余风险、重试上限；持续告警 | 把清仓请求当作仓位归零 |
| 未知请求超过配置超时 | 中 | 升级核对 / 告警 | 自动释放预占或重发 |
| 策略心跳超时 | 高 | 按配置：告警等待人工，或申请接管（§7） | 心跳超时直接授予交易权 |
| 过期控制命令被拒绝 | 中 | 计数；连续出现时告警 | — |
| 阶段权限冲突（日历与 InstrumentStatus） | 中 | 采用保守门禁 | 用全账户"开市"布尔值放行 |
| 生命周期超时（越过预计窗口未就绪） | 高 | 保持门禁 | 按预计时间自动恢复 |

## 5. 日志规范与脱敏

来源：规划 §8.2、第二章第 2 项、§4.6。

- 日志从基础阶段启用，每条至少关联：账户别名、策略、`controller_id` / `control_epoch`、`client_order_id`、柜台标识、`journal_seq`、交易日、规则版本。
- 交易回报保存必要的脱敏原文；账户、`AppID`、`AuthCode` 等凭证通过本地秘密配置加载，不进入代码仓库、日志或实验快照。
- 终端采集载荷及原始终端标识（MAC、IP、采集密文）不在日志、实验快照或故障附件中保存；A27 验证。
- 结算中的原始半结算查询与最后一致快照分开保存，不混入行情 Parquet。
- 告警与风险状态转换写入结构化事件，含触发原因、时间、解除条件与操作人。
- 不静默吞异常；异常进入日志并映射到 §4.2 的动作。

## 6. 备份与恢复演练

来源：规划 §5.4 第 1 项、§4.5 第 5 项、§4.6。

| 项目 | 要求 |
| :--- | :--- |
| 备份方式 | 使用 SQLite 备份接口或一致性快照（`backup_state.py`）；不在活跃 WAL 模式下仅复制主数据库文件 |
| 备份内容 | `live/trading.db`（控制记录、订单意图、事件、账本、预占、计数、游标、快照）与 `meta/control.db`；记录对应 `journal_seq` 与校验信息 |
| 频率 | 日终结算对账完成后；关键操作（接管、熔断解除）后可加做 |
| PRAGMA | `journal_mode = WAL`、`synchronous = FULL`、`foreign_keys = ON`、`busy_timeout = 5000`；按实际 SQLite 版本检查生效 |
| Checkpoint 与保留 | Checkpoint 策略、备份保留期纳入运维配置 |
| 恢复约束 | 从备份恢复不得回退或复用已使用的控制代次；先恢复控制记录再推进代次；无法确认最新控制记录时停止自动接管 |
| 恢复演练 | 定期（建议每月至少一次，与 A18 的备份恢复证据对齐）从备份离线恢复并运行 `replay_events.py` 比较订单、预占、账本差异 |
| 存储位置 | 数据库位于本地受支持磁盘；不用网络共享文件承担多进程交易协调 |
| 故障场景 | 在目标文件系统验证进程崩溃、断电、磁盘满后的恢复（A14） |

## 7. 应急处置手册

来源：规划 §4.5 第 3、5、6 项，§4.6，§4.4 第 4 项。每项处置均经唯一执行服务、同一风控与记账路径，并留审计记录。

### 7.1 策略失联

| 项目 | 内容 |
| :--- | :--- |
| 触发 | 独立监控进程检测策略心跳超时 |
| 允许动作 | 按配置：告警等待人工；或申请接管后撤单 / 减仓 |
| 禁止动作 | 心跳超时本身授予交易权；旧控制者恢复后其过期代次命令被接受 |
| 恢复条件 | 人工确认策略状态；如已接管，按 7.2 完成后由新控制者决定是否恢复策略 |

### 7.2 看门狗接管

| 项目 | 内容 |
| :--- | :--- |
| 触发 | 7.1 配置为接管，或人工发起 |
| 允许动作 | 顺序固定：执行服务先停发旧控制者命令 → 在账户执行序列内持久化新控制者与新代次 → 拒绝旧代次排队命令；明确未发送的请求按失败事件释放预占 → 执行 05 §16 对账，核对已发送及结果未知请求 → 一致后新控制者按配置撤单或减仓 |
| 禁止动作 | 对账完成前撤单 / 减仓；旧交易出口未确认停止或未经独立机制隔离时另建交易连接接管 |
| 恢复条件 | 接管过程写入交易事件库；异常原因消除、账户一致、风险状态明确重置后才可恢复交易 |

### 7.3 人工接管竞争

| 项目 | 内容 |
| :--- | :--- |
| 触发 | 多个操作者同时尝试 `control.py` 影响交易状态的命令 |
| 允许动作 | 只有当前控制者，或完成 7.2 正式接管的控制者，其命令携带有效代次被执行 |
| 禁止动作 | 通过人工命令绕过控制代次校验 |
| 恢复条件 | 审计记录确认唯一有效控制者 |

### 7.4 执行服务重启 / 故障

| 项目 | 内容 |
| :--- | :--- |
| 触发 | 执行服务进程退出或崩溃 |
| 允许动作 | 重启后先恢复已持久化的控制记录，再推进代次并拒绝此前控制命令；进入 `RECONCILING` |
| 禁止动作 | 单纯 CTP 重连自动切换控制者；从备份恢复回退或复用代次；无法确认最新控制记录时自动接管 |
| 恢复条件 | 05 §16 流程五步全部通过 → `READY`；`READY` 不自动解除既有熔断 |

### 7.5 整机故障（断电、整机网络失联）

| 项目 | 内容 |
| :--- | :--- |
| 触发 | 独立于交易主机的存活告警触发 |
| 允许动作 | 人工按已验证的应急处置路径处理（联系期货公司、通过其他已授权终端撤单 / 减仓）；期货公司条件单等托管保护仅在能力表核验后作为备份 |
| 禁止动作 | 假定同机看门狗仍在工作；视托管保护为必定能平仓 |
| 恢复条件 | 主机恢复后按 7.4 处理；另一终端产生的委托在重连对账时识别为外部委托 |

### 7.6 熔断与清仓失败

| 项目 | 内容 |
| :--- | :--- |
| 触发 | 风控进入 `REDUCE_ONLY` → `CANCELING` → `FLATTENING` → `HALTED`；或清仓请求因行情过期、断线、涨跌停、限流无法成交 |
| 允许动作 | 先禁止新增风险，撤销冲突或增加风险的挂单，撤单回报与迟到成交核对后按实际剩余仓位分批减仓；撤单与减仓获得较高调度优先级并预留请求预算 |
| 禁止动作 | 为"紧急清仓"绕过监管、柜台硬限制、真实可平仓量和资金检查；把发出清仓请求等同于仓位归零；普通开仓冷却阻断合法减仓 |
| 恢复条件 | `HALTED` 期间继续处理回报、对账和监控；异常原因消除、账户一致、风险状态明确重置后才恢复交易 |

### 7.7 结算单差异

| 项目 | 内容 |
| :--- | :--- |
| 触发 | `parse_statement.py` 比对差异超过约定误差 |
| 允许动作 | 禁止新增风险；人工逐项核对；确认后以差额更正事件入账（不覆盖旧账、不重复计入收益） |
| 禁止动作 | 直接修改账本匹配结算单；忽略差异继续开仓 |
| 恢复条件 | 差异全部解释且更正事件入账 |

### 7.8 外部委托发现

| 项目 | 内容 |
| :--- | :--- |
| 触发 | 重连查询发现本地未知的活动订单或持仓差异 |
| 允许动作 | 识别并输出差异；建立带远端标识的占位记录；人工确认归属 |
| 禁止动作 | 猜配到本地订单；擅自按外部委托补开仓；一致前进入 `READY` |
| 恢复条件 | 差异处置完成，账户一致 |

## 8. 运行环境要求

## 9. 影子模式与执行校准流程

来源：规划 §6.5、A24。

1. **影子模式**：接入真实 CTP 行情，策略与共享内核正常运行，执行端口接模拟撮合；记录每个订单意图的假设成交价、数量与时刻。
2. **小额并行**：通过首笔实盘门槛后，以最小手数并行运行；同一订单意图分别进入模拟撮合与唯一真实执行服务，按实际合约、方向、触发时点及手数关联比较成交价、数量、耗时和未成交比例；数量不同的结果单独列示。
3. **周报**（`shadow_report.py`）：实际滑点对假设滑点、实际成交率对假设成交率、耗时分布、按品种和时段的分布及样本数量；区分实时观测、历史回放和故障注入；列出尚未在真实市场观察到的条件与规模。
4. **不可外推标记**：偏差持续超出敏感性分析覆盖范围时，回测结论标记为不可外推，成本参数重新校准。
5. **时长与场景分别验收**：影子模式与最小手数并行实盘连续运行至少一个完整自然月，交易时段与维护中断均留痕；换月、长假前后、涨跌停及断线等场景按 A18 另行覆盖；未自然发生的场景可用版本化历史回放或故障注入补齐，但不折抵运行时长，不计入实际滑点、成交率或容量证据。
6. **扩大范围**：最小手数成交证据只支持已观察的规模与条件；每次增量单独评估并持续校准。
