## 目的与读者

本文档按共享领域内核的组件逐一定义业务规则：每节给出规则说明、状态图或不变量（文本）、边界情形、关联需求与验收。读者是实现 `domain/`、`gateway/simulated_gateway.py`、`gateway/feedback_normalizer.py` 与 `data/calendar.py` 的开发者，以及编写 A 系列验收用例的测试者。组件在系统中的位置、端口与进程拓扑见 04 文档；本文不重复架构内容。

引用约定：`来源：规划 §x.y` 指向规划原文；`FR-*` 指向 02 需求拆解的需求编号；`A01`—`A29`、`A25-0x` 指向规划 §9.2 验收案例。凡规划标注"须核验 / 不能作为默认"的交易所、柜台事实，本文保留同样措辞；任何时段、超时、费率数值均为核验基线或测试输入，不是生产默认。

通用约定：

- 未知能力禁止实盘使用；未核验条目按原规划第二章及 09 登记缺口。
- 精确核算模式（FR-SCOPE-05）遇关键规则或数据缺失即中止并说明缺项；研究模式使用显式假设并在报告中标注。
- 所有状态转换、预占变更与记账在账户执行序列内串行完成，并按同一事务提交（04 §6）。回测使用内存 Journal 保持同样提交语义；模拟盘与实盘使用持久化适配器。
- 交易命令走控制权与事前风控分支；订单/成交事实走校验、关联、去重与入账分支，真实成交不因过期代次、既有熔断或当前资金不足而丢弃。新的风险处置命令再通过命令分支执行。

## 1. 平仓路由与能力表映射

来源：规划 §4.1.1；FR-ORD-01、FR-ORD-02；验收 A01。

### 规则说明

- 内部订单使用开仓、平今、平昨等明确意图，由适配器映射到实际柜台字段。持仓归属、手续费归属、CTP 报单标志是三个相关但不同的概念：统一平仓指令也不能省略费用归属核算。
- SHFE / INE 的今昨仓路由需单独验证；DCE / GFEX / CZCE / CFFEX 也应逐项验证显式平今、平昨及统一平仓的支持情况、分配顺序和计费方式。不得仅凭 CTP 枚举中存在某标志就认定目标柜台支持，也不得把统一平仓等同于今昨手续费相同。
- 能力配置键至少包含 `exchange + product + broker_profile + ctp_version + effective_from`，并记录规则来源及实测用例。未知能力禁止实盘使用。
- 平仓顺序由账户规则和策略配置决定，不能在网关中写死"所有品种优先平昨"。

### 能力表必须逐项核验的行为

保存目标期货公司、CTP / 柜台版本、生效区间、测试输入与脱敏结果；以下核验项不能作为所有柜台通用的既定事实：

| 核验项 | 要求 |
| :--- | :--- |
| 撤单标识 | 保存原订单的 `FrontID + SessionID + OrderRef` 与 `ExchangeID + OrderSysID`。跨会话优先使用已核验的交易所 / 系统编号路径；原订单三元组能否跨会话使用须实测，不得将新登录的前置、会话编号与旧 `OrderRef` 拼接。`OrderSysID` 尚未取得时等待回报、查询，或使用另一条已验证路径，不因超时盲目撤单或重发订单。 |
| 今昨仓查询 | 核验 `YdPosition` 是日初量还是剩余量，以及 `PositionDate`、持仓方向、投机 / 套保标志的分组语义。若 `YdPosition` 为日初口径，不能直接当作盘中昨仓余量；仅在确认总仓与今仓均为同组剩余数量后，才用 `Position - TodayPosition` 推算。SHFE / INE 的今昨分条记录按实际返回口径归一化，禁止重复汇总，并与平今、平昨成交核对。 |
| 查询流控 | 查询间隔、最大在途请求数、返回码与完成标志按目标柜台核验并配置。可从间隔 1000 ms、最多一个在途查询的保守配置开始测试，但不能视为通用限额或成功保证；遇到限流需退避，查询未完成不得当作完整快照。 |
| 前置维护 | 按端点记录已知重启和维护窗口，重点验证结算前后及夜盘前的恢复；日常运维定期演练重连与对账，不假定每个前置每天都在固定时间重启。 |

能力表还至少覆盖（规划 §2.2）：开平映射、报单类型、有效期、分阶段报撤权限、休市预埋支持、查询限制、撤单口径、手续费、保证金及交割限制；区分本地受理、柜台接受与交易所受理的证据。

### 边界情形

- 能力键在查询时点无唯一匹配：拒绝下单并报告缺口，不回退到"最接近"的配置。
- 策略指定的平仓意图（如平今）在目标柜台不支持：明确拒绝（A01），不静默转换为统一平仓。

## 2. 持仓与逐单预占

来源：规划 §4.1.2；FR-ORD-03；验收 A02、A08。

### 不变量

按账户、实际合约、持仓方向和投机 / 套保标志维护 `pos_yd`、`pos_td`、`frozen_yd`、`frozen_td`；冻结量由逐单预占记录汇总，四个数量字段本身不构成订单状态机。

```text
available_yd = pos_yd - frozen_yd
available_td = pos_td - frozen_td
0 <= frozen_yd <= pos_yd
0 <= frozen_td <= pos_td
```

### 规则说明

- `SmartRouter` 先生成不修改状态的子订单计划。账户执行序列对最终子订单统一检查，并在同一事务内记录订单意图、冻结持仓、预占保证金与费用。
- 开仓预占按未成交部分的保守成交价格计算；平仓单也需预留可能的手续费及组合保证金变化。子订单的报撤额度分别计数。
- 每笔去重后的成交只更新一次持仓、冻结与账本。成交后将相应预占转换为实际占用，剩余活动数量继续预占。
- 撤单或拒单只释放已确认不会成交的部分。撤单请求发送或接口返回成功，不表示原订单已经撤销。
- 若终态订单回报中的累计成交量大于已入账成交量，保留差额对应的冻结，等待迟到成交或查询确认；不能因先收到终态就全部解冻。

### 边界情形

- 部分成交后撤单成功：只释放未成交部分的冻结，已成交部分转为实际占用。
- 终态回报累计成交量 > 已入账成交量：差额冻结保留，进入待关联 / 对账；见 §3。
- 今昨仓转换（§5 第 6 条）时，`frozen_td` 随 `pos_td` 一并转入昨仓，逐单预占记录的归属同步更新，不得出现 `frozen_td > pos_td`。

## 3. 订单状态机与回报语义

来源：规划 §4.1.3；FR-ORD-04、FR-ORD-05；验收 A02、A04。

### 状态与必须执行的处理

| 状态或事件 | 必须执行的处理 |
| :--- | :--- |
| `CREATED / SUBMITTING` | 提交前持久化意图与预占，分配稳定的 `client_order_id`，保存父子订单关系。 |
| `ACCEPTED / PARTIALLY_FILLED` | 保存柜台订单标识与累计成交信息，按唯一成交记账，不依靠回调到达顺序推断全部事实。 |
| `FILLED / CANCELED / REJECTED / EXPIRED` | 作为已确认终态；迟到状态不能使订单倒退，迟到但尚未入账的真实成交仍需处理。 |
| `cancel_pending` | 作为独立撤单状态，可与部分成交并存。撤单拒绝后原委托可能仍有效，预占继续保留。 |
| `UNKNOWN` | 发送、连接或恢复过程中无法确定柜台结果；保留保守预占并进入对账，不把超时自动转换为拒单。 |
| 明确未发送的本地失败 | 记录失败原因并释放相应预占；能否认定"未发送"必须由适配器的明确返回语义决定。 |

状态图（文本）：

```text
CREATED -> SUBMITTING -> ACCEPTED -> PARTIALLY_FILLED -> FILLED
                |            |             |
                |            +---- cancel_pending（正交标志，可与 ACCEPTED / PARTIALLY_FILLED 并存）
                |                          |
                +-> UNKNOWN（发送 / 恢复不确定，进入对账）
                |
                +-> REJECTED（明确拒绝）   ACCEPTED/PARTIALLY_FILLED -> CANCELED / EXPIRED
终态之后：状态不倒退；累计成交事实独立维护，仍可补记迟到成交。
```

### 网关覆盖范围

网关须覆盖本地调用返回、`OnRspOrderInsert`、`OnErrRtnOrderInsert`、`OnRtnOrder`、`OnRtnTrade` 及撤单错误回报，将其转换成统一领域事件。同一事实通过多种回调重复到达时，业务结果不重复计算。

### CTPFeedbackNormalizer 三条规则

`CTPFeedbackNormalizer` 负责字段校验、标识关联与事件归一化，具体账本变更仍由共享内核执行：

1. **关联前提**：本地意图及原会话订单映射必须在报单前存在。成交先于报单回报时，优先使用已核验作用域内的 `ExchangeID + OrderSysID` 或可唯一关联的原会话订单映射绑定；`OrderRef` 不能单独作为跨会话唯一键，成交回报未携带原会话信息时也不能补上当前会话号猜测关联。
2. **待关联成交占位**：无法唯一归属的真实成交先持久化为待关联事件，并建立带远端标识的占位记录。在确认本地订单关联或核实为外部成交前，不猜配、不释放其他订单的预占，不发布受其影响的可交易账户快照。确认后在同一账户执行序列中一次性入账、合并占位并重建相关预占；仅策略归属仍未知的保留"未分配策略"标签，差异处置完成前禁止新增风险。不能因缺少本地订单或 `OrderSysID` 映射丢弃成交，也不能擅自按外部委托补开仓。
3. **迟到报单回报**：补全占位记录与原意图的关系，只合并标识、归属及预占，不再次生成成交记账。订单终态与累计成交事实分开维护，`CANCELED` 后仍可补记迟到成交，不因迟到的"已报"回报退回活动状态；无法解释的超量或归属冲突进入对账。

### 边界情形

- 成交先于报单回报（A02）：按规则 1、2 处理；真实成交不丢失且只记一次。
- 跨会话 `OrderRef` 冲突（A02）：不误绑定；进入待关联。
- 终态后迟到成交（A02）：入账；冻结不变量成立。

## 4. 发送状态三态

来源：规划 §4.1.4；FR-ORD-06、FR-ORD-07；验收 A03、A04。

`send_state` 与订单成交 / 撤销状态正交，保存每次发送尝试及证据：

| 发送状态 | 判定依据与处理 |
| :--- | :--- |
| `NOT_SENT` | 适配器能证明尚未调用发送，或已核验的返回语义明确表示请求未送出；记录失败后释放相应预占。不能把所有异常或非零返回统一归为未发送。 |
| `SENT_UNKNOWN` | 本地调用已受理但缺少远端确认，或发送结果本身不确定；保留预占，禁止盲目重发，交由恢复协调器核对。`ReqOrderInsert` 返回 0 不代表柜台接受或成交。 |
| `CONFIRMED_REMOTE` | 已有可关联的远端订单、成交或明确拒绝证据；按实际订单结果推进状态，远端确认不等于报单成功。 |

### 重连核对原则

- 重连后按查询能力及流控立即开始核对，保存查询范围、交易日、完成标志与回报合并水位。
- 告警与人工介入超时按柜台配置；30 秒可作为测试参数，不能作为通用最短挂起时间或"订单不存在"的证据。
- 超时、一次空查询或查无此单均不自动释放未知预占或重发；只有确认未发送 / 未受理或核实远端终态后才关闭未决状态。

### 边界情形

- 本地返回 0 后断线（A03）：`SENT_UNKNOWN`，预占保留，进入对账。
- 空查询（A03）：只升级核对 / 告警，不自动重发原意图。
- 重新使用同一个本地编号不等于柜台会自动去重（规划 §4.6.1）。

## 5. 交易日历、交易日映射与结算事件

来源：规划 §4.2；FR-CAL-01—06；验收 A05、A06。

1. **交易时段表**：按交易所、品种、合约例外和生效区间记录交易日、竞价、连续交易、休市、夜盘跨日、节假日及临时停市。区分品种通常支持夜盘与某交易日实际存在夜盘；最晚交易日和最后交易日的特殊时段也纳入规则。
2. **交易日映射**：由具体时段映射到 `trading_day`。普通非节假日周五夜盘通常归入下一周一交易日，但不能用"自然日期加一天"或"下一个工作日"代替期货日历；周六凌晨的夜盘仍属于对应交易时段。
3. **来源校验**：保留 CTP 的 `TradingDay`、`ActionDay` 等原始字段，并结合端点规则与日历校验后生成统一时间。模拟端点使用独立配置，不默认继承实盘日历。
4. **收盘事件**：按合约适用时段生成 `SessionClosed`；不能统一写死 15:00，例如中金所国债期货常规收盘时间为 15:15，具体历史时段仍按版本化日历执行。
5. **结算事件**：官方结算数据经完整性检查后生成带交易日及版本的 `SettlementReady`，驱动账本结算。数据尚未就绪时标记 `SETTLEMENT_PENDING`，不得静默用收盘价替代。
6. **今昨仓转换**：在已确认的 `TradingDayAdvanced` 事件中完成一次性转换，并核对待结算状态、上一交易日订单及冻结。晚到回报按其原交易日处理；跨日订单的失效或继续有效遵循柜台规则，不能直接清空全部挂单。

补充规则：行情到达下一交易日时继续采集，但上日结算或账户对账未完成，应阻止新增风险。结算修订通过有版本的差额更正事件处理，不覆盖旧账，也不重复计入收益。

### 边界情形

- 周五夜盘、周六凌晨、节假日前后、无夜盘品种及特殊收盘时段（A05）：交易日、Bar 边界、计数重置与今昨仓转换均符合样例日历。
- 结算价迟到、非报价 Tick 的结算价、重复结算及修订（A06）：待结算状态明确；每个版本只生效一次；更正留痕；已结转盈亏不再次增加权益。

## 6. 交易阶段 MarketPhase 与操作权限

来源：规划 §4.2 交易小节、集合竞价与操作权限；FR-CAL-07—11；验收 A25 及子用例。

### 阶段枚举与权限

`MarketPhase` 按实际合约维护：竞价申报、竞价撮合、只撤不报、等待连续交易、连续交易、小节休市、停牌、收盘及未知状态。阶段与 `session_id` 分开，不为每个日夜盘小节复制一套枚举。申报、撮合属于集合竞价，等待与连续交易属于后续市场阶段；并非所有品种都必经同一流程，也不人为规定固定长度的等待阶段或为每次小节恢复补一次竞价。

每个阶段分别配置 `can_submit()`、`can_cancel()`、`can_match()`，包含订单类型、受理层级及生效规则：

| 阶段 | can_submit | can_cancel | can_match | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| 开盘竞价申报 | true | true | false | 核验值 |
| 竞价撮合 | false | false | true | 撮合窗口允许执行规定的竞价撮合，不表示该分钟内可按每个 Tick 连续撮合 |
| 只撤不报 | false | true | false | 不能把开盘前五分钟视为整段可撤单时间 |
| 连续交易 | true | true | true | |
| 小节休市 / 午休 | 按能力表 | 按能力表 | false | 报撤权限单独核验，不能从"不撮合"推导所有请求都会被拒绝 |
| 未知 | 保守门禁 | 保守门禁 | false | 状态缺失、过期或冲突时采取已配置的保守门禁并告警 |

时段边界按左闭右开区间处理，截止时刻已经进入下一阶段。

### 时段核验基线（非生产默认）

下表按时间底稿列出常规核验基线，时区为 `Asia/Shanghai`。生产及历史精确核算使用第二章要求的一手规则与已核验版本；其中历史调整日期仍须关联原公告，新增或特殊品种另行配置。

| 适用场景 | 时段及操作要求 | 版本与边界 |
| :--- | :--- | :--- |
| SHFE / INE / DCE / CZCE / GFEX 商品日盘 | 常规连续交易为 09:00–10:15、10:30–11:30、13:30–15:00；小休与午休不撮合，报撤权限单独核验。 | 五个商品交易场所均有常规 10:15–10:30 小休，豆粕、甲醇不能按该时段连续交易建模。 |
| 无夜盘商品的日盘开盘 | 08:55–08:59 申报、08:59–09:00 撮合，09:00 进入连续交易。 | 仅为实际适用的日盘开盘竞价生成事件；10:30、13:30 恢复交易不自动补竞价。 |
| 实际开设的夜盘开盘 | 20:55–20:59 申报、20:59–21:00 撮合，21:00 进入连续交易。 | 夜盘是否存在及 23:00 / 次日 01:00 / 02:30 等收盘分档按品种和历史版本配置，不从交易所名称统一推导。 |

| CFFEX 国债历史及最后交易日 | 时间底稿记载 2020-07-20 起上午开盘由 09:15 调整至 09:30，开盘竞价随之由 09:10–09:15 调整至 09:25–09:30；最后交易日仅上午交易。 | 历史样例只使用当时已挂牌合约并匹配适用细则；最后交易日下午不生成可撮合时段。 |

### 夜盘残留单

夜盘残留单按订单有效期、交易日及阶段转换规则决定进入日盘竞价、继续等待或失效，保存原订单标识、累计成交和剩余预占。日夜盘切换不重建同一订单、不重复预占或计费，也不自动把仍有效委托清空；失效、撤销及迟到成交继续按 §3 的确认语义处理。

### 节假日与特殊公告

- 节前停夜盘及节后恢复直接依据交易所放假公告生成实际时段，不能用"假日前一自然日晚上"或普通工作日公式推算。例如长假从周一开始、周五为最后交易日时，仅关闭周日夜盘会漏掉周五的取消安排。
- 若公告规定节后首日日盘集合竞价，应覆盖常规夜盘品种的日盘模板，尤其验证 CZCE 的只撤不报窗口；覆盖关系、适用交易日与原公告一起保存。
- GFEX 当前无夜盘及其规则预留按时间底稿登记，实际接入时复核最新公告；未来开通夜盘须重新确认，不能由现行预留条款自动启用。
- 期权属于后续扩展；若启用中金所股指期权，另行核验 14:57–15:00 收盘竞价的报撤、价格形成及订单延续规则，不照搬开盘 4+1 分钟模型。

### InstrumentStatus 门禁

日历与 `OnRtnInstrumentStatus` 等可用状态回报共同确定实时权限，记录来源、接收时间和有效范围；状态缺失、过期或冲突时采取已配置的保守门禁并告警，不能用一条全账户的"开市"布尔值覆盖所有品种。区分本地保存意图、柜台预埋、交易所报单 / 撤单受理与实际撮合；休市期预埋或撤单能力须单独核验，预埋受理不等于可撮合订单。

### 本地发送前与到达时双重检查

本地发送前与模拟到达时分别检查权限。若撤单在申报窗口发出、在禁止撤单阶段才到达，应产生撤单拒绝并保留原单及预占，之后的竞价成交正常入账；可配置截止前的安全缓冲，但不能保证请求一定赶到。没有竞价数据时，Bar 模式不得凭连续交易 Open 宣称复现了集合竞价成交；按执行策略拒绝该撮合假设或显式改为连续交易后的可观测价格。

### 边界情形（对应 A25 子用例）

- A25-01 小休 / 午休不生成成交；报撤受理按独立能力配置判断。
- A25-02 rb / m 进入日盘竞价，MA 只撤不报；残留单不重复建单、预占或计费。
- A25-03 2023-05-26 生效边界：旧、新规则分别命中；不按自然日 00:00 错切版本。
- A25-04 撤单 08:58:58 发出、08:59:01 到达，及恰在 08:59:00 到达：按左闭右开进入不可撤阶段则拒绝，原单及预占继续存在。
- A25-05 节假日公告：不产生已取消的夜盘；节后日盘竞价覆盖只撤模板。
- A25-06 国债开盘时间调整前后及最后交易日。
- A25-07 仅有连续交易 Bar Open：拒绝竞价成交假设或按事前声明降级；不回填已过去的开盘成交。

## 7. 每日生命周期 DailyLifecycleManager

来源：规划 §4.2 每日生命周期协调；FR-CAL-12；验收 A26。

### 运行阶段

按端点及账户维护 `PRE_OPEN / RUNNING / POST_CLOSE / SETTLEMENT_IN_PROGRESS / MAINTENANCE / RECONCILING` 等运行阶段；它与合约交易阶段（§6）、连接状态（§16）、风控状态（§13）分别管理，不能压成一个全局状态机。维护与结算时间是带来源的预计窗口，实际转换还依赖连接、结算及查询证据，不写死每天 15:30 断开、18:30 恢复或把 20:55 当作连续交易开盘。

### 四条规则

1. 某品种收盘不等于账户所有品种均已结束交易；按所选合约时段及柜台信号安排收盘任务，避免商品 15:00 收盘时误停仍在交易的国债期货。
2. 结算中收到的资金 / 持仓查询保存为待核对原始快照，附交易日、查询批次及完整性标记；持仓已切换、资金未结转时不能覆盖最后一致的可交易账户快照。登录成功或结算确认应答本身不能证明新交易日数据已完整。
3. 结算未完成或快照不一致时禁止新增风险；行情采集、回报处理、对账、告警及基于最后一致状态的保守风险评估继续运行。不可把"禁止使用半结算数据"实现成关闭风控；撤单 / 减仓仍须通过 §12、§16 的控制权、状态及资金检查。
4. 仅在结算单所属交易日与完整性核验、必要的结算确认、账户查询及增量回报核对完成后，才发布一致快照并申请恢复。

### 幂等

任务按账户、交易日、事件类型及版本幂等执行，重启不重复结算、转换今昨仓或重置计数；越过预计窗口仍未就绪时保持门禁并告警。

### 边界情形（A26）

- 半结算查询：持仓已切换而资金未结转的快照不覆盖最后一致状态。
- 维护延迟：越过开盘仍未就绪则保持门禁。
- 日终重启：重复日终任务不重复结算、转换持仓或清零计数。

## 8. 主力映射、连续序列与移仓

来源：规划 §4.3；FR-CON-01—07；验收 A10、A29。

### 8.1 当时可获知的主力映射

- 主力判定使用决策时点已经可用的成交量、持仓量及合约资格数据。若使用 T 日完整日盘数据，默认不早于 T+1 交易日首个可交易时段生效，并要求输入已达到 `available_at`、决策已完成；若数据迟到则顺延，不能回填为 T 日已交易的主力。
- 保存 `decision_time`、`effective_from`、候选合约、输入数据版本及选择规则；并列、流动性门槛、连续确认天数和避免频繁切换的条件必须确定。
- 主力识别以当时已知的品种活跃月份结构为先验，按品种和历史生效区间配置；1、5、9 月或 1、5、10 月只是部分品种的候选示例，不能统一套用。在候选范围内按成交量与持仓量判定，并要求连续确认天数，避免逐日抖动。

### 8.2 ContractResolver

- 对实际合约使用稳定标识，包含交易所及完整交割年月；保留原始柜台代码，避免简称、大小写或郑商所短年份代码在多年数据中混淆。
- 郑商所短年份代码通过 `ContractResolver` 解析。例如 `TA405` 必须结合行情记录所属交易日、数据源说明及当时有效的合约目录，解析到含完整年份的内部标识，如 `CZCE.TA.202405`；`TA2405` 仍只是常见的两位年份供应商别名。
- 不得按程序运行当天年份解释历史文件，也不能仅用 `current_year ± 1` 代替合约上市 / 到期区间。候选范围由具体品种的挂牌规则与合约元数据限定；跨年、跨十年或缺少日期导致无法唯一解析时隔离并报错，不猜测归属。保留原代码、来源日期、解析依据与目录版本（A29）。

### 8.3 三种视图

原始拼接价、连续指标价与收益率视图分别定义：

- 策略可通过价差平移或比例复权计算连续指标，但每个时点只能使用当时已生成的映射和复权因子。禁止将回测结束后生成的整段后复权历史直接用于所有历史决策。
- 切换日不能把"新合约今日收盘 / 旧合约昨日收盘 − 1"当作可交易收益；用于动量的收益率可按当时选定同一实际合约的相邻价格计算，或采用经过验证的连续收益构造，并保存两端合约、时刻、调整因子及可见时间。
- 价格平移与比例复权的适用指标不同，价差平移后的价格百分比变化不能直接当作真实资金收益。不能简单把所有切换日收益置零或删除交易日；缺少调整参考价时明确标记、禁用受影响信号或采用已声明的降级方案。
- 策略发出的意图须解析为明确实际合约；成交、费用、持仓估值、涨跌停和保证金均使用该合约未经连续复权的原始价格。
- 数据查询接口区分实际合约与连续序列，保存复权方法、参考价及版本。缺少真实合约数据时，不输出可与实盘对账的资金结果。

### 8.4 主力识别与账户移仓解耦

`data/dominant_contract.py` 只产生带可见时间及生效时间的主力映射；`data/continuous.py` 据此生成指标 / 收益率视图。`domain/rollover.py` 中的 `RollManager` 通过映射查询端口消费已发布版本，结合账户实际持仓和策略参数独立执行移仓，不自行扫描数据文件或重算主力。映射变化不自动修改仓位，两者分别记录并分别报告。

### 8.5 移仓时点与腿序

- 移仓时点作为策略参数，可选主力切换生效日、已确认持仓量交叉后的第 N 个交易日（N >= 0），或已知最晚平仓日前 N 个交易日，并允许分批执行。输入须满足 `available_at <= decision_time`；保存触发事实、决策时间、规则与日历版本，不得从未来实际交叉日倒推提前移仓。
- 若后续引入交叉日期预测，须保存决策当时生成的预测、模型及输入版本；未来实际交叉日期不能替代历史预测。规则迟到时按当时状态处理，不回填此前的移仓决策。
- 腿序可配置：保证金充足且临时敞口符合账户限制时可默认先开新仓再平旧仓；否则按配置先平后开或暂停。两腿之间的临时双倍敞口、空仓窗口及部分成交风险均计入风控评估。
- 临近交割时依据账户资格及期货公司最晚平仓要求提前触发处理。

### 8.6 两腿移仓状态机

```text
PLANNED -> LEG_1 -> LEG_2 -> DONE
                   任一阶段异常 -> PAUSED / FAILED（保留已成交事实）
```

每条腿均经过订单管理与风控，并处理部分成交、撤单、重试上限、涨跌停、交易时段及保证金不足；未完成移仓时报告实际剩余持仓和风险暴露。

### 8.7 移仓成本与归因

移仓的实际资金损益来自真实两腿成交及后续持仓变化，手续费逐笔计算，滑点体现在成交价格中。不得额外固定扣除"双倍手续费＋两倍滑点"，以免重复计费。报告将新旧合约价差、执行费用与滑点、持仓收益及注明基准的展期收益归因分别列示；合约间价差本身不是新增现金损益，不得再记入账本。

### 边界情形（A10）

- 仅未来交叉日不同的成对样本：既往决策一致。
- 新旧合约各自价格不变而存在价差：切换不产生虚假动量或账本盈利。
- 两腿部分成交及资金不足：主力映射不直接改变持仓；先开后平满足资金与敞口限制；费用逐笔计一次；失败报告真实剩余仓位。

## 9. 资金账本

来源：规划 §4.4.1；FR-LED-01—04、FR-LED-09；验收 A06、A22。

### 统一记账口径

- 建立不可变的成交、费用、资金划转、结算和差额更正记录。账本由事件推导，策略收益不包含入金、出金等外部现金流。
- 今仓初始计价基准为成交价，昨仓为上一结算价。平仓按所平持仓当前计价基准确认盈亏；日终只对剩余持仓计提到官方结算价的盈亏，并更新下一交易日基准。
- 盘中动态权益由已结余额与未实现盈亏等账户项目计算。原始开仓价可用于交易绩效分析，但已经划入余额的每日结算盈亏不能再次加入动态权益。
- 报单价格比较优先转换为整数 Tick；结算价、均价、金额和费率保留所需定点精度或使用 `Decimal`，按账户规定的计费粒度及舍入规则核算。与柜台比较时明确最小金额单位和允许误差。
- 最新价格过期、盘口缺失或处于涨跌停流动性不足状态时，记录估值质量并使用配置的保守风险估值，不将长期未变化的最新价当成可立即平仓价格。

### 两种盈亏视图（共享一套事实）

不维护两套可各自增加余额的账本：

| 视图 | 计算基准 | 用途 |
| :--- | :--- | :--- |
| `mtm_close_pnl`（逐日盯市平仓盈亏） | 今仓按实际开仓价，昨仓按上一结算价；分别计算多空方向、乘数与对应平仓数量。 | 日常结算对账，并结合持仓盯市、费用、冻结和账户规则计算权益与风险。 |
| `trade_close_pnl`（逐笔交易平仓盈亏） | 平仓价与所匹配原始开仓批次的价格比较，跨日保留开仓成本及费用分摊。 | 扣费后的胜率、盈亏比、平均持仓时间及策略归因；配对规则、部分平仓与策略归属须固定。 |

### 手工验收样例

无手续费、1 手多仓、乘数 10，100 开仓，当日结算 110，次日 108 平仓：

| 事件 | mtm 视图 | trade 视图 | 权益变化 |
| :--- | :--- | :--- | :--- |
| 首日结算 | +100 | — | +100 |
| 次日平仓 | −20 | +80 | −20 |
| 合计 | +80 | +80 | +80 |

最终权益合计增加 80，不能再把逐笔 +80 叠加到账本。夏普、回撤、月度收益使用包含未平仓估值并剔除外部现金流的时间序列权益；不能只用已平仓交易盈亏代替。

### 边界情形

- 结算修订：通过有版本的差额更正事件处理，不覆盖旧账，不重复计入收益（A06）。
- 部分平仓与费用分摊：配对规则固定并可追溯（A22）。

## 10. 保证金与可用资金

来源：规划 §4.4.2；FR-LED-05、FR-LED-06；验收 A08。

### 规则说明

账户模型需区分持仓保证金、活动订单的增量保证金、待扣费用和其他冻结，并避免把柜台已包含的冻结重复扣减。模型与柜台余额、权益、可用资金等字段的映射必须通过对账样例确认。

浮盈能否参与开仓、风险度或保证金覆盖，按交易所结算口径、期货公司、账户权限及生效规则核验，不能统一断言"浮盈一定能开仓"或"一定不能开仓"。

### 三个字段

- `broker_available`：柜台查询的原始可用资金，附交易日、查询时点、来源与一致性状态；先核验其是否已包含浮盈浮亏、保证金及冻结，不能再次重复扣减。
- `available_for_new_trades`：按该账户开仓资金规则得到的额度，同时检查现有活动订单的增量需求。盈利可计入比例、浮亏扣减、按合约还是账户汇总、费用与冻结的处理均版本化；不能直接把动态权益当作开仓额度。
- `margin_coverage_equity`：用于保证金覆盖及风险度评估的权益口径，注明分子与所比较保证金的定义。它与开仓额度是同一账户的不同视图，不能相加作为两笔可用资金，也不能因计入浮盈就直接减去法定保证金需求。

### 大边优惠

单向大边或组合优惠由账户、品种、合约组合、方向、投机 / 套保标志及历史生效规则共同决定，不能仅按交易所名称套用 `max(多头, 空头)`。只有已验证的组合规则才启用优惠；锁仓单边平仓可能改变优惠，减仓前也要重算资金需求。

### 缺失规则时的两种模式

- 研究模式：缺少历史浮盈使用规则时，可显式采用"浮盈不增加开仓额度、浮亏按保守口径扣减"的假设并做敏感性分析；已通过结算划入余额的盈利须按新交易日规则处理，不能永久当作未实现浮盈扣除。缺失保证金规则时按第二章第 6 项使用交易所公告比例加固定缓冲，并以保证金占用率上限作为风控规则。
- 实盘及精确核算模式：以已核验的账户规则和一致查询为准，差异未解释时阻止新增风险；缺失保证金规则时中止。

风控同时评估现有持仓及所有活动委托可能成交后的资金需求。

### 边界情形（A08）

- 并发开仓与活动占款：检查与预占原子执行。
- 允许 / 不允许浮盈开仓的配置分别符合预期；结算转入余额后按新日规则处理。
- 开仓与保证金覆盖视图不相加；冻结不重复扣减；平仓后的资金需求正确重算。

## 11. 追保、强平与结算单对账

来源：规划 §4.4.3、§4.4.4；FR-LED-07、FR-LED-08；验收 A22。

### 追保与强平

按期货公司规则建模盘中和盘后保证金检查、追保期限、资金到账以及强平处理，不假定所有账户均等到次日开盘集合竞价才强平。强平委托也受时段、涨跌停、流动性和柜台限制约束；无法成交时保留真实仓位、持续告警并报告未解决风险。

### 结算单对账

期货公司每日结算单是账户资金、持仓、盈亏与费用的权威口径，柜台实时查询只是中间状态。系统交付结算单解析器（`data/statement.py`），解析逐日盯市与逐笔对冲两种平仓盈亏、手续费、保证金占用及持仓明细，并在每个交易日结算确认后自动与本地账本逐项比对，输出差异报告。差异超过约定误差时禁止新增风险，直到人工确认或更正事件入账。

### 边界情形（A22）

- 资金、持仓、盯市 / 逐笔平仓盈亏及费用与各自正确口径一致；§9 的样例对齐；差异触发禁止新增风险。

## 12. 事前风控流水线

来源：规划 §4.5 引言、§4.5.1、§4.5.2；FR-RISK-01—04；验收 A19、A08。

风控是所有策略、移仓、看门狗及人工交易指令的必经路径。独立执行服务按账户串行执行控制权核验、风控校验和预占，网络发送在本地事务提交后进行；控制权切换与发送使用同一执行序列，避免校验通过后被旧控制者继续发单。

```text
Strategy / RollManager / RiskReduction / Watchdog / 人工控制发出意图
     |
SmartRouter 生成最终子订单计划（不修改账户状态）
     |
账户执行序列：核验控制者与代次、规则、价格数量、自成交、资金、敞口、报撤额度
     |
同一事务：保存订单意图 + 冻结持仓 / 资金 + 预占报单额度
     |
ExecutionPort 发送前复核控制代次 -> 统一回报事件 -> 去重并更新账本与预占
```

### 三类规则分别管理

| 规则类别 | 配置要求 |
| :--- | :--- |
| 交易所及监管要求 | 记录来源文件、发布日期、生效时间、账户或实际控制关系范围、计数单位及例外；以当前适用版本核验。 |
| 期货公司及柜台限制 | 记录请求速率、查询限制、报单类型、撤单口径、保证金和账户权限；通过指定柜台测试。 |
| 内部风险偏好 | 配置品种与账户资金上限、活动订单敞口、亏损 / 回撤指标、行情过期阈值及风险状态转换。 |

### 计数与持久化

撤单总数、撤单率、频繁报撤次数和持仓比例不设置无来源的生产默认值。日内回撤需明确基准、峰值更新及现金流调整方法。不同规则分别定义统计窗口、分母、重置交易日，以及请求、接受、撤销或成交哪个事件触发计数；计数随事件持久化，重启不得清零。

### 交易所硬约束（进内核，回测与实盘同一实现）

至少包含：中金所品种的日内开仓限额和撤单次数限制；各交易所按合约阶段递减的一般持仓限额；自然人客户在多数商品品种进入交割月前的最晚平仓要求；上市首日及连续单边市后的涨跌停幅度与保证金调整。这些约束在阶段 3 的回测验收中生效，使策略违规在回测报告中可见，不能推迟到模拟盘才发现（A19）。

### 自成交与账户范围

- 检查同合约反向活动订单价格是否可能交叉，并包含正在发送、撤单未确认及未知状态委托。风险校验和活动订单登记在同一账户执行序列中完成，避免两个并发意图分别通过检查。
- 首版要求账户交易入口受控，重连时同步人工或其他终端产生的委托。发现无法识别的活动订单或持仓差异时禁止新增风险。
- 涉及多个实际控制关系账户时，需要统一账户视图或柜台侧控制，不能声称单进程本地挂单簿已覆盖全部监管范围。

## 13. 熔断状态机

来源：规划 §4.5.3；FR-RISK-05；验收 A09。

```text
NORMAL -> REDUCE_ONLY -> CANCELING -> FLATTENING -> HALTED
```

五条规则：

1. 触发熔断后先禁止新增风险，再按规则撤销冲突或增加风险的挂单；在撤单回报与迟到成交核对后，按实际剩余仓位分批减仓。
2. 撤单和减仓可获得高于普通开仓的调度优先级，并预留可用请求预算，但仍须遵守监管、柜台硬限制、真实可平仓量和资金检查。
3. 自身普通开仓冷却条件不应阻断合法减仓。内部限制应按增加风险、撤单和降低风险分别配置，禁止为"紧急清仓"绕过全部校验。
4. 行情过期、断线、涨跌停或限流导致无法清仓时，保留未完成状态、剩余风险、重试上限和告警；不能把发出清仓请求等同于仓位归零。
5. 进入 `HALTED` 后仍处理回报、对账和监控；恢复交易前要求异常原因消除、账户一致且风险状态明确重置。`READY`（§16）不自动解除既有熔断或暂停状态。

### 边界情形（A09）

- 熔断时仍有挂单、内部冷却、柜台限流或无法平仓：合法减仓不被普通开仓冷却误拦；仍遵守硬限制；未成交风险持续可见。

## 14. 控制权、唯一交易出口与接管

来源：规划 §4.5.5；FR-RISK-07、FR-RISK-08；验收 A23。

运行在应用进程内的止损与熔断逻辑随承载进程退出而失效。不能仅凭 CTP 字段或枚举推定存在交易所 / 柜台托管止损；触发地点、有效期及断线后的存续能力须按目标柜台核验，未核验时按无托管保护设计。

### 五条规则

1. **唯一交易出口**：独立执行服务是本系统唯一持有该账户 CTP 交易连接的进程，实施单实例约束。策略、看门狗与人工控制通过该服务操作，不各自登录交易接口。服务持久化当前 `controller_id` 与单调递增的 `control_epoch`，对开仓、平仓 / 减仓、撤单、改单及恢复交易命令，在接收和最终发送 / 生效前校验控制权；所有系统内的发送路径均不得绕过。
2. **失联不等于退出**：独立监控进程检测策略心跳。超时后的默认处置须配置为告警等待人工，或申请接管后撤单 / 减仓；心跳超时本身不授予交易权。暂停后恢复或网络恢复的旧控制者仍持有过期代次，其命令必须被拒绝。
3. **接管顺序**：执行服务先停发旧控制者命令，在账户执行序列内持久化新控制者及新代次，再拒绝旧代次排队命令；明确未发送的请求按失败事件释放预占。随后执行 §16 对账，核对此前已发送及发送结果未知的请求，一致后才允许新控制者按配置撤单或减仓。已提交到柜台的请求不会因代次变更消失，其预占与迟到回报继续处理；接管过程写入交易事件库。
4. **执行服务故障**：执行服务重启或控制者变更时，先恢复已持久化的控制记录，再推进代次，拒绝此前的控制命令；单纯 CTP 连接重连不自动切换控制者。从备份恢复不得回退或复用已使用代次，无法确认最新控制记录时停止自动接管。若旧交易出口不能被确认停止或经独立机制隔离，不得仅凭心跳超时另建交易连接接管，保持禁止新增风险并告警，由人工按已验证流程处置。
5. **整机故障与备份保护**：同机看门狗不能覆盖主机断电或整机网络失联。部署独立于交易主机的存活告警，并验证人工应急处置路径；期货公司条件单等托管保护经能力表核验后可作为备份，其触发、失效及与本地订单冲突的处理须测试，不视为必定能平仓。

### 接管序列（文本）

```text
心跳超时 -> 看门狗申请接管
  -> 执行服务：停发旧控制者命令
  -> 执行序列内持久化 (controller_id_new, control_epoch+1)
  -> 拒绝旧代次排队命令；明确未发送的请求释放预占
  -> §16 对账（已发送 / 未知请求核对）
  -> 一致后：新控制者可按配置撤单 / 减仓
  -> 全过程写入交易事件库
```

### 边界情形（A23）

- 旧代次开仓、平仓、撤单、改单及恢复命令均被拒绝；已发送请求的迟到成交仍正确入账。
- 重启 / 备份恢复不复用旧代次；无法隔离旧出口时不另建连接自动交易；过程可审计。

## 15. 人工命令与开盘检查清单

来源：规划 §4.5.6；FR-RISK-09。

### 人工命令

提供命令行级别的人工控制：暂停新增风险、撤销全部挂单、按品种或全部减仓、查询当前状态与差异、确认差异后恢复。影响交易状态的人工命令须由当前控制者执行，或完成 §14 接管后执行；均经过唯一执行服务、同一风控与记账路径并留审计记录，不能通过人工命令绕过控制代次校验。

### 开盘前检查清单

每个适用交易时段开盘前，按版本化日历与配置的提前量执行：

| 检查项 | 内容 |
| :--- | :--- |
| 唯一执行服务及控制代次 | 单实例存活；当前控制记录可确认 |
| 连接与登录 | 认证 / 采集结果、登录状态 |
| 交易日与结算确认 | 结算完整性、必要的结算确认 |
| 行情时效 | 行情年龄在阈值内 |
| 规则版本 | 日历、能力表、费用与保证金版本已加载且唯一 |
| 账户对账状态 | 无未解释差异；对账中则保持禁止新增风险 |
| 监控及外部告警可用性 | 看门狗、独立存活告警可用 |

08:55 / 20:55 仅是部分常规时段提前五分钟的示例；节假日、取消夜盘及特殊开盘时间以日历为准。开盘时仍处于对账中的账户保持禁止新增风险，并告警。

【评审补充】本机时钟偏差检查项待 04 文档 ADR-X3 确认后加入，状态待确认。

## 16. 持久化、幂等与恢复流程

来源：规划 §4.6；FR-REC-01—05；验收 A02—A04、A14、A23。

### 事件库字段

使用独立交易事件库保存 `client_order_id`、父子订单关系、账户 / 策略归属、`controller_id` / `control_epoch`、`send_state`、柜台标识映射、待关联成交、规范事件、逐单预占及递增 `journal_seq`。交易回报保存必要的脱敏原文，终端采集载荷及凭证不落盘；旧代次请求的真实成交仍按订单标识入账，不能当作过期命令丢弃。

### 去重键

成交去重键由适配器按柜台编号的真实唯一性范围定义，通常需要账户、交易所、交易日及成交编号等组合；必要时包含合约或方向。不能只用 `OrderRef` 或 `TradeID` 单字段跨会话去重。

### 事务与游标

提交失败不发布未提交的可交易视图；回滚暂存变更或从最后已提交状态重建。禁止发送未持久化的增加风险意图，不能用失败事务释放远端结果未知请求的预占。订单/成交事实无法可靠保存时立即禁止新增风险并进入核对与告警；行情录制容忍度不适用于交易事实。

- 事件去重、账本更新、预占变更和处理游标在同一事务提交。快照保存对应 `journal_seq`，恢复时从明确游标重放，避免"快照加全部历史成交"重复入账。
- 本地数据库事务不能与远端 CTP 报单原子提交。"意图已保存但是否发送未知"以及"柜台已接受但回报丢失"均须进入核对流程；重新使用同一个本地编号不等于柜台会自动去重。

### 启动与重连流程

```text
DISCONNECTED -> RECOVERING -> RECONCILING -> READY
                                  |
                         差异未解决：保持禁止新增风险
```

1. 先确认执行服务单实例及旧出口隔离状态，恢复持久化控制记录；服务重启或接管时按 §14 推进代次并拒绝旧命令，单纯重连不自动授权另一个控制者。加载已提交快照与后续事件，恢复订单、预占、持仓、账本和报撤计数，将无法确认远端结果的请求标记为未知。
2. 按已核验的接入模式完成终端采集 / 注册、认证、登录及必要的结算确认，顺序以能力表为准；结合生命周期检查交易日与结算完整性，重新订阅行情。按查询间隔、在途上限和退避规则查询资金、持仓、订单与可获得的成交记录，保留原订单标识供跨会话核对与撤单。
3. 查询期间缓存并按序保存实时回报。订单、成交、持仓和资金查询通常不是同一原子快照，需依据查询完成标志、所属交易日、结算状态、游标和重复查询建立一致视图，避免先覆盖持仓再重放相同成交；半结算或跨交易日混合的查询不能发布为可交易快照。
4. 识别外部委托与未知发送结果，按唯一事件重建预占，输出逐项差异。若柜台查询范围不足以确认状态，保持未知并提供可人工核对的记录，不推测已拒单后重发。
5. 在唯一交易出口、当前控制权、交易连接、行情时效、交易日、待结算状态、订单、持仓及资金全部通过一致性检查后切换为 `READY`。`READY` 不自动解除既有熔断或暂停状态；未解决差异、恢复超时和重复断线均须告警。

### 故障注入清单

验收需注入：柜台接受后断线、重复及乱序回报、部分成交后进程终止、查询中继续成交、磁盘写入失败。恢复成功以柜台状态与本地账本一致为准，连接重新建立本身不构成成功。

### 边界情形

- A04：游标重放和查询合并不重复记账；撤单使用实测支持的原订单标识；限流或未完成查询不被视为完整快照；能识别外部订单及差异，一致前不进入 `READY`。
- A14：交易意图未落盘时不继续增加风险；无虚假的持久化成功记录。

## 17. Bar 撮合模型

来源：规划 §6.1.1、§6.1.2；FR-MATCH-01—05；验收 A11、A20。

### 因果约束

使用完整 Bar T 的收盘信息生成订单后，最早只能在订单实际生效后的行情上撮合，通常为下一可交易 Bar。这约束的是时序因果与前视偏差，不能代替防过拟合的样本外验证。此前已经生效的订单可以在 Bar T 内成交，不能笼统禁止所有当前 Bar 成交。

### 订单生效与成交候选

| 订单场景 | 撮合条件与价格边界 |
| :--- | :--- |
| 主动成交意图 | 根据柜台能力转换为支持的订单类型，如带价格保护的限价单。仅在订单生效、时段及流动性条件满足时生成候选成交。 |
| 集合竞价、只撤窗口与小节休市 | 请求到达时按 §6 核验报撤权限，撮合独立检查 `can_match()`；只撤窗口不接收新交易所委托且不撮合，撤单被拒绝不改变原单终态。集合竞价价格、数量及参与资格缺失时，不使用连续交易 Bar 冒充竞价撮合。 |
| 下一 Bar 开盘成交 | 必须在该开盘时点前已经生效，且满足竞价或连续交易规则；否则不能使用该 Bar 的开盘价。 |
| 限价买单 | `Low <= LimitPrice` 仅说明价格到达。开盘可成交时，候选价可由 `Open + 滑点` 得到，但不得高于限价或超出有效价格边界。 |
| 限价卖单 | `High >= LimitPrice` 仅说明价格到达。开盘可成交时，候选价可由 `Open - 滑点` 得到，但不得低于限价或超出有效价格边界。 |
| 盘中触及限价 | 配置"触价允许候选成交"及"穿价至少一个 Tick 才允许候选成交"等情景，结合成交量预算生成部分成交，不保证触价后全部成交。 |
| 涨跌停 | 使用候选成交时点适用的实际涨跌停边界与价格 / 交易状态，开盘候选不能因随后收盘触板而被否定。无更细盘口时按下述显式流动性情景评估；上市首日及连续单边市后的幅度调整使用当时实际边界并保留来源。对应 A20。 |

### 竞价成交模型限制

启用竞价成交模型时，价格形成、并列价格处理、同价分配、有效期及未成交申报延续分别绑定适用交易所规则与可用数据；不能仅凭一所的"最大成交量"条款实现全市场竞价算法，也不能把开盘模型用于收盘竞价。只检查时段合法性不要求首版重建竞价盘口；不能支持竞价成交的策略按 §6、A25-07 明确选择可验证的执行方式。

若订单在 Bar 内才生效而没有更细数据，保守模式延至下一完整 Bar 评估，避免使用可能发生在订单到达之前的最高价或最低价。无有效行情、零成交量、休市、停牌及价格边界不明时，按质量与订单规则处理，不能补造可成交价格。

### 开盘候选与 Bar 结束估算分开

开盘价格判断只使用该时点的信息；完整 Bar 的高低价、收盘状态及"一字板"分类，只能在 Bar 结束时用于评估尚未成交的订单，不能改写已确定的开盘成交。仅有 OHLCV 时，不推断触板与回落的盘中先后顺序。

### `limit_liquidity_scenario`（写入运行清单）

- **方向保守（默认研究假设）**：候选时点处于涨停价时假设买单不成交，卖单仅在已观测成交量、共享参与率预算、订单生效时点及价格约束均满足时允许候选成交；跌停反向处理。这是缺少盘口时的保守假设，不代表真实涨停买单绝不成交或卖单必然成交。
- **触板无成交（压力情景）**：对候选时点价格已处于涨跌停边界的新候选成交，两方向均假设不成交，并在报告中单列结果。一字板只表明该 Bar 内成交价格未变，并不能证明成交量为零或双向均无流动性；不得把压力假设写成市场事实，也不能根据后来的完整 Bar 分类撤销此前已确定的成交。

### 成交量、事件顺序与局限

- 定义 `participation_rate`，将本账户在同一 Bar 的可模拟成交量限制为规范成交量的一个比例；多个策略和订单共享预算，禁止每个订单各自使用整根 Bar 的全部成交量。使用整根 Bar 成交量是事后容量近似，不能证明开盘时可成交的数量；需要验证开盘容量时须使用对应时段的更细成交或盘口数据。
- 候选价格、可用数量、排队情景和订单有效期共同决定部分成交。成交价始终满足订单限价、价格步长和涨跌停约束。
- Bar 无法提供可靠的盘中价格路径。默认在该 Bar 处理完成时才向策略公开本 Bar 的模拟成交结果，禁止利用完整高低价或总成交量进行同 Bar 追单和重复换手。
- 同一 Bar 同时触及止盈、止损等互斥条件时，采用预先约定的保守路径或转用更细数据；禁止按最终收益选择有利顺序。
- 报告列出信号与执行数据分辨率、成交量预算、涨跌停流动性情景、触价规则和成交时刻近似。需要盘中连续反应的策略须升级数据与撮合模型。

### 边界情形

- A11：信号不回填到此前价格成交；成交量预算共享；部分成交及限价边界正确；不读取未来 Bar 或未知盘中路径。
- A20：固定开盘输入及数量预算，仅改变后来收盘是否触板，既有开盘成交必须不变；一字板有量样例按方向保守假设及共享预算评估；零量不成交。

## 18. 执行时点策略

来源：规划 §6.1.3；FR-EXEC-01—03；验收 A21。

信号频率不决定执行价格的数据粒度。执行时点按品种的版本化日历、信号 `available_at`、计算 / 报单延迟及订单生效规则确定，区分集合竞价与连续交易。常规情况下，部分有夜盘品种的日线信号可在当晚 21:00 执行，无夜盘品种可能在下一交易日日盘开盘执行；节前无夜盘、临时停市、特殊开盘时间及信号迟到均须重新选择实际可用时段，不能写死"自然日加一天"或统一 09:00 / 21:00。

| 执行策略 | 所需执行数据与约束 |
| :--- | :--- |
| 下一可交易时段开盘 | 明确归属目标夜盘 / 日盘时段的开盘或竞价价格。只有数据源定义证实日线 Open 正是所选时段、时刻的价格时，才允许使用它。 |
| 下一日盘开盘 | 独立的日盘开盘价或足以识别该开盘的盘中数据；包含夜盘的交易日日线 Open 通常不能提供日盘开盘价。 |
| 下一日盘收盘前固定时间 | 与所选时刻对齐的分钟或更细价格，按日历计算相对收盘的偏移；不能用当日日线 Close 代替，也不能用尚未完成的分钟 Bar 收盘价提前成交。 |
| 下一 Bar 开盘（适用于小时级等信号） | 对应实际合约的下一可用 Bar 开盘价及明确的时段边界；订单须在该开盘撮合前已生效。 |

### 错过与缺价处置

- 上述策略均须先确定信号可见时间，再检查订单能否赶上目标撮合时点。
- 错过目标开盘时，按预先配置顺延到下一符合条件的目标开盘或取消，不回填已过去的开盘成交；仅有开盘价不代表订单参与了集合竞价。
- 所选执行价格缺失或分辨率不足时，明确禁用该执行策略或中止实验，不静默改用其他时段的价格，也不插值补造价格。
- 配置、日历及执行数据来源写入运行清单。

### 边界情形（A21）

- 日夜盘开盘价不同的样例按配置使用正确来源与交易日；含夜盘日线 Open 不冒充日盘 Open。
- 节假日及特殊开盘遵循日历；信号 / 订单迟到不回填过去开盘。
- 固定盘中时刻缺价或分辨率不足时明确失败。

## 19. Tick 撮合与排队估算

来源：规划 §6.2；FR-MATCH-06；验收 A12。按策略类别在阶段 7 启用；首版保留设计。

CTP 常见行情属于间隔不固定的盘口快照，不能直接还原完整订单队列。数据源的 Tick 是快照还是逐笔记录，应写入运行清单。

1. **委托合法性**：先检查目标柜台支持的订单类型、有效期、价格步长及该交易日涨跌停边界。不支持的报单拒绝或按已配置的转换规则处理。
2. **涨跌停成交**：最新价触及涨跌停并不自动意味着委托无效；有效委托能否成交取决于方向、对手盘、排队及有效期。无对手流动性时保留未成交或按订单有效期结束。
3. **主动成交**：按生效后可用的对手价量及保守成交量预算模拟；不能用过期盘口无条件填满订单。超出可见深度的数量应限制、分批或采用明确的冲击假设。
4. **被动排队**：初始化估计的前方队列，区分该价位可能成交的数量、撤单与新增挂单。不能把全市场所有价位的累计成交量全部用于消耗我方队列。
5. **部分成交**：估计队列耗尽后仍按剩余可成交量逐步成交，队列耗尽不意味着整笔委托立即全部成交。
6. **不确定性**：队列倍数、成交方向推断、撤单分配和冲击参数以真实行情与成交观测校准，并输出多种情景；仿真对比用于逻辑验证，不能替代真实排队证据。L1 模型结果需标注为排队估算，不宣称交易所级精确重放。

### 边界情形（A12）

- 委托合法性与成交条件分别判断；无流动性不虚构成交；排队与部分成交遵守所选情景。A12 的订单合法性部分适用于所有策略（首笔实盘门槛）；排队部分按类别启用。

## 20. 基于时间的延迟事件

来源：规划 §6.3；FR-MATCH-07；验收 A13。

采用基于时间的事件调度，分别配置报单到达、撤单到达、订单回报、成交回报及行情传输延迟，使用毫秒或更细的真实时间单位。参数可为常量或固定随机种子的分布，来自实际观测或明确标注的压力情景。

- `cancel_arrival_at = cancel_sent_at + cancel_delay_ms` 只表示模拟请求到达。到达时须通过时段、订单及柜台权限检查，撤单被接受并完成处理后才生成 `cancel_effective_at`；被拒绝的撤单不生成生效事件，原单继续有效。实盘按已确认回报处理，不能用本地计时替代撤单确认，迟到成交仍进入共享订单状态机。
- 定时事件即使没有新 Tick 也应推进；不能用"两 Tick"表示固定网络延迟。500ms 间隔下两 Tick 约一秒，稀疏行情时则可能更长。
- 行情、订单到达与回报延迟独立建模，不让策略提前看到尚未到达的成交或盘口。相同时刻的成交与撤单按固定、可测试的顺序处理。
- 当行情分辨率粗于待模拟延迟时，使用保守的后续可观测行情或多情景结果，并标注分辨率限制；不能凭快照插值声称恢复了真实亚秒成交路径。

### 边界情形（A13）

- 定时器独立于 Tick 数推进；到达不等于生效；被拒绝的撤单不终结原单；有效撤单前成交正常入账，生效后不再产生新成交；迟到回报仍处理。

## 21. 长假前降风险钩子

来源：规划 §4.5.4；FR-RISK-06。

交易日历标记长假及其前后交易日，并关联交易所保证金和涨跌停调整公告。风控提供节前若干交易日按比例减仓或降杠杆的钩子，参数按品种与策略配置；复市后的恢复条件明确定义。回测中同样执行，使历史收益反映节前处理的成本。

### 边界情形

- 节前无夜盘（A21、A25-05）：钩子触发的减仓意图按实际可用时段执行，不写死自然日。
- 节前保证金调整公告：进入 §10 的保证金规则版本，与钩子分别记录。

## 22. 规则查询与费用计算

来源：规划 §2.5、§2.6、§5.4.2；FR-RULE-01—05；验收 A07。

### 费用公式

常规线性手续费公式：

```text
费用 = 手数 × 每手费用 + 成交价格 × 合约乘数 × 手数 × 金额费率
```

再按对应规则舍入。纯按手或纯按金额时，另一分量为零；最低收费等特殊规则需显式扩展并测试。

A07 单位样例：2 手、价格 1000、乘数 10、每手 1.5 元、费率 0.0001 时合计 5 元；这些是测试输入，不是实际品种费率。

### 生效区间与唯一性

规则查询区分业务生效时刻 `effective_at` 与查询者可获知时刻 `known_at`：策略和事前风控的查询视图不得越过当前策略时钟；晚发布规则在账务中通过独立更正事件处理。`domain/rules.py` 消费注入的规则端口和值对象，SQLite 读取及迁移归基础设施适配器（04 §4.5）。

- 生效区间按 `[effective_from, effective_to)` 解释，需支持日内调整。相同查询时点与账户下的适用规则必须唯一；历史修订保留旧版本，并规定替代关系和查询优先级。
- 成交记账按实际生效规则计费；策略和事前风控只能读取当时可获知的版本（`available_at`）。
- 开仓、平今、平昨费率按品种、合约、账户及生效区间分别记录，注明按手或按金额计费、期货公司加收与舍入口径；不得套用交易所统一的平今费率倍数。历史平今费率变化会改变日内策略的可行性，不得用当前费率回填历史。

### 来源区分

- 规范费用表保存该账户最终适用的总费率。原始来源记录区分交易所费用、期货公司加收和期货公司已报总费率，避免再次叠加已包含的费用。
- 每条规则包含发布机构、标题 / 文号、原文位置、归档文件与哈希、发布日期、适用范围、生效基准（交易日或物理时刻）、生效区间、替代关系、核验状态及对应测试编号。第三方汇总仅作为查找线索。
- 网页核验日期不等于规则生效日期；缺少一手原文或无法唯一判断适用版本时，登记受影响范围，不伪造历史配置。

### 晚发布与更正

晚发布的费用或结算更正按更正事件入账，不能提前提供给策略。历史发布时间不可考时，明确标记时间假设及其回测限制。

### 研究模式默认成本假设

研究模式不因缺失历史期货公司费率或保证金而中止，使用下表显式假设并在报告中标注；精确核算模式仍中止：

| 项目 | 默认假设 | 说明 |
| :--- | :--- | :--- |
| 滑点 | 主力合约每边 1 个最小变动价位，非主力合约每边 2 到 3 个 | 敏感性分析至少覆盖每边 0、1、2、3 跳 |
| 手续费 | 交易所公告费率，期货公司加收按交易所费率的固定比例假设 | 平今费率使用公告历史，不得用开仓费率代替 |
| 保证金 | 交易所公告比例加固定缓冲 | 保证金占用率上限作为内部风控规则 |
| 成交量参与率 | Bar 成交量的固定比例 | 具体比例作为实验参数记录 |

这些数值是研究假设，不是任何品种的实际费率；进入模拟盘前必须以能力表和期货公司实际费率替换。

### 边界情形（A07）

- 按手、按金额、组合收费、平今平昨差异、券商加收及日内变更：费用与独立手工账一致。
