## 1. 背景与问题陈述

### 1.1 为什么要自建

- **回测与实盘共享内核**。市面常见做法是回测一套持仓 / 资金算法、实盘另一套，导致回测盈利在实盘上无法复现。规划要求回测与实盘共享订单状态机、平仓路由、持仓与资金账本、规则查询、风控及移仓逻辑，并明确禁止两边各自维护资金或持仓算法（来源：规划 §3.4）。
- **中国期货特有规则**。平今 / 平昨与手续费归属、夜盘所属交易日、合约到期与换月、逐日盯市与保证金、异常交易监控、网络与进程故障下的订单三态，这六个维度决定了通用框架不能直接使用（来源：规划 §1 表）。
- **连续合约不可交易**。连续合约仅用于信号计算；实际成交、费用、保证金和结算发生在有到期日的具体合约上（来源：规划 §1 引言、§4.3）。

### 1.2 参考架构的局限

原参考架构（统一 CLI、Strategy API、Parquet + DuckDB + SQLite 分层存储、向量化信号研究）的可保留部分是分层存储、实验快照和独立运维工具（来源：规划 §3.1、§3.2）。其局限在于：

| 参考设计 | 局限 | 本项目处理（来源：规划 §3.3） |
| :--- | :--- | :--- |
| 永续合约资金费率 | 中国普通期货不适用 | 不建模；基本面策略另提供基差、期限结构、仓单接口并保留发布时间 |
| 向量化 `signal {-1,0,1}` | 忽略成交、资金、风控 | 保留为快速研究通道，用保守成本假设粗筛；正式评估走事件驱动内核 |
| 离线研究入口 | 无执行、无恢复 | 增加统一执行端口、CTP 适配器、持久化订单管理与恢复对账 |
| GUI、遗传编程、复杂路由 | 非关键路径 | 交易与数据基础验收后按需扩展 |

原规划引用的架构图 `HD95DUJbwAA5tej.jpg` 当前目录不存在，实施以规划定义的接口与验收条件为准（来源：规划 §3.1）。

### 1.3 实施原则

采用薄切片路线：先以简化撮合得到第一条可逐笔对账的权益曲线并开始策略研究，再逐步补齐恢复、存储与精细撮合（来源：规划 §1.2、§9.1）。【评审补充，PROP-01】建议在 S3 内增加 S3a 最小闭环作为内部里程碑，随后由 S3b 完成原 S3 全部出口；S3a 不替代 S3 验收，不把既定硬约束后移到 S4。状态：待确认。

## 2. 项目目标

**一句话目标**：交付一个面向中国期货、回测与实盘共享交易内核、可逐笔对账并以真实执行偏差为外推依据的自动交易与回测工具。

**分层目标**（来源：规划引言、§9.1）：

1. 可逐笔对账的单账户 Bar 回测与向量化快速研究通道。
2. 多品种移仓、模拟盘、看门狗、影子模式与最小手数实盘。
3. 按策略类别启用 Tick 仿真与精细撮合。
4. 生产能力以规则核验、故障恢复、结算单对账和真实执行偏差为依据，而非以功能列表为依据。

**修订原则**（来源：规划 §1.2）：真实资金损失后果 > 回测收益失真 > 研究效率。策略稳健性验证与真实成交校准是扩大资金的必要依据。

## 4. 范围

### 4.1 首版范围（来源：规划 §1 末段、§1.1）

- 平台：Windows；账户：单账户；标的：普通期货合约。
- 回测：面向日线 / 小时级信号的 Bar 事件驱动回测，CLI 报告。
- 策略类别：多品种低频 CTA。信号频率与执行价格的数据粒度分别配置。
- 样例：先螺纹钢实际合约，再覆盖第二交割月及甲醇等跨交易所场景。
- 向量化快速研究通道与事件驱动回测通道并存，共用数据映射、执行时点、价格来源与成本口径（来源：规划 §3.3）。

### 4.2 后续扩展（来源：规划 §1 末段、§9.1 阶段 7）

期权、跨账户协同、组合保证金优化、GUI、遗传编程、低延迟交易；分钟级日内与 Tick 级策略能力在低频闭环验收后按类别启用；Tick 录制、撮合、排队估算随类别启用。

### 4.3 明确不做 / 显式禁用

- 尚未实现的规则在运行配置中明确禁用，不以"默认支持"出现（来源：规划 §1 末段）。
- 中金所品种只在确实要交易时加入；中金所股指期权收盘竞价另行核验（来源：规划 §2.4、§4.2）。
- GUI、复杂组合保证金、因子进化与低延迟优化不占用首个可对账闭环的关键路径（来源：规划 §9.1 末段）。
- 本地开发机不承担实盘运行（来源：规划 §4.5.5）。

## 5. 目标策略类别与分层要求

策略类别决定数据分辨率、撮合模型、成本敏感度和验证方式，是所有后续设计的前置决策。未声明类别的实验和账户不得进入模拟盘或实盘（来源：规划 §1.1）。

| 类别 | 典型持仓周期 | 首版必需的数据与撮合 | 可推迟的能力 | 必须上调优先级的事项 |
| :--- | :--- | :--- | :--- | :--- |
| 低频 CTA（日线 / 小时级，多品种） | 数日到数月 | 实际合约信号 Bar、结算价、涨跌停价、执行策略所需时段开盘或盘中价格；Bar 撮合加固定跳数滑点 | Tick 录制、盘口排队、亚秒延迟仿真 | 执行时点及其数据覆盖、移仓价差、多品种跨周期样本、长假处理 |
| 分钟级日内 | 分钟到数小时 | 实际合约 1 分钟 Bar、当日实际涨跌停价、分时段成交量；Bar 撮合加参与率 | 盘口排队估算 | 平今费率历史、成交量参与率、延迟与执行校准 |
| Tick 级 | 秒到分钟 | 原始快照录制自阶段 0 开始、Tick 撮合、基于时间的延迟事件 | 无 | 排队估算校准、影子模式、报撤限制 |

首版目标类别为多品种低频 CTA。类别声明写入实验清单，报告按类别列出所用撮合模型及其局限。

## 6. 核心认知：规则维度与系统要求

（来源：规划 §1 表，完整保留）

| 规则维度 | 设计依据 | 对系统的要求 |
| :--- | :--- | :--- |
| 平今、平昨与平仓指令 | 持仓归属、手续费归属、CTP 报单标志是三个相关但不同的概念。SHFE / INE 需区分今昨仓；各交易所的具体指令映射以柜台能力核验为准。 | 内部保留今昨仓及逐单冻结；按能力表映射报单，统一平仓指令也不能省略费用归属核算。 |
| 夜盘与交易日 | 夜盘所属交易日由交易日历确定，受节假日、品种和临时停市影响。存在日盘、夜盘、集合竞价及不同收盘时间。 | 使用版本化交易时段；分别保存物理时间与交易日，以交易日事件驱动今昨仓转换。 |
| 合约到期与换月 | 连续合约是派生研究序列，实际成交发生在有到期日的具体合约上。 | 保存当时可获知的主力映射，用真实合约价格、费用和保证金模拟移仓；纳入账户交割资格与最晚平仓日限制。 |
| 杠杆与逐日盯市 | 结算依据官方结算价，保证金还受账户、品种、合约、持仓组合和生效时间影响。 | 共享资金账本，区分盘中估值与正式结算，核算活动订单占款及盘中、盘后追保。 |
| 异常交易监控 | 监管限制、柜台流控和内部风险偏好有不同的口径与适用范围。 | 前置风控覆盖最终子订单和账户活动委托，保留规则版本；熔断过程可恢复、可追踪。 |
| 网络与进程故障 | 请求返回、柜台接受、交易所成交和回报到达并非同一个事件。 | 持久化订单意图与回报，按唯一事件记账；未知状态先对账，禁止盲目重发。 |

## 11. 术语表

| 术语 | 定义 |
| :--- | :--- |
| 今仓 / 昨仓 | 当前交易日新开的持仓 / 上一交易日结转的持仓；在 `TradingDayAdvanced` 事件中一次性转换。 |
| 平今 / 平昨 / 统一平仓 | 平仓意图的三种归属；持仓归属、手续费归属与 CTP 报单标志是三个不同概念，映射以能力表为准。 |
| 逐单预占 | 每笔活动订单单独记录冻结持仓、预占保证金与费用；仅 frozen_yd、frozen_td 由逐单预占汇总，pos_yd、pos_td 由成交及跨日等持仓事实推导。 |
| 能力表 | 按交易所、品种、柜台配置、CTP 版本、生效区间记录柜台支持的开平映射、报单类型、报撤权限等，附来源与测试证据；未知能力禁止实盘。 |
| 主力映射 | 按决策时点可用数据判定的品种主力合约，含 `decision_time`、`effective_from` 与输入版本。 |
| 连续合约 / 连续序列 | 按当时可见映射拼接的派生研究序列，仅用于信号；不可交易、不可记账。 |
| 移仓（换月） | 账户从旧合约切换到新合约的两腿交易，由 `RollManager` 消费已发布映射独立执行。 |
| 逐日盯市（`mtm_close_pnl`） | 今仓按开仓价、昨仓按上一结算价计算的平仓盈亏；用于结算对账。 |
| 逐笔对冲（`trade_close_pnl`） | 平仓价对匹配原始开仓批次价格的盈亏；用于策略绩效分析。 |
| `available_at` | 回测中允许策略获知某记录的最早时间；策略只能查询 `available_at <= 当前策略时钟` 的数据。 |
| 账户执行序列 | 同一账户内串行执行控制权核验、风控、预占、发送与回报入账的单一序列。 |
| 控制者 / 控制代次（`controller_id` / `control_epoch`） | 当前拥有交易权的实体及其单调递增代次；旧代次命令一律拒绝。 |
| 唯一交易出口 | 独占账户 CTP 交易连接的独立执行服务，单实例。 |
| `send_state` 三态 | `NOT_SENT`（明确未发送）、`SENT_UNKNOWN`（缺少远端确认或发送结果本身不确定）、`CONFIRMED_REMOTE`（远端有确认证据，含明确拒绝）。 |
| 待关联成交 | 无法唯一归属本地订单的真实成交，持久化为占位记录，确认前不猜配、不释放他单预占。 |
| 半结算 | 柜台持仓已切换到新交易日而资金尚未结转的中间状态；其查询结果不得覆盖最后一致快照。 |
| 只撤不报 | 仅允许撤单、不接受新报单也不撮合的交易阶段，`can_submit=false / can_cancel=true / can_match=false`；不能因其处于开盘前就认定正在进行集合竞价。 |
| 再竞价 | 有夜盘品种在日盘开盘前再次进行的集合竞价（时间底稿记载三所自 2023-05-26 起，须按原公告核验）。 |
| 夜盘残留单 | 夜盘未成交、按有效期与阶段规则延续到日盘的委托。 |
| 研究模式 / 精确核算模式 | 研究模式在缺失费率 / 保证金时用显式假设并标注；精确核算模式缺项即中止。 |
| 向量化通道 / 事件驱动通道 | 前者基于拼接序列做快速参数扫描；后者在共享内核上做成交、资金、风控评估。 |
| ExecutionReference | 从确实覆盖所选执行时点的原始数据派生的执行价格视图。 |
| `limit_liquidity_scenario` | 涨跌停时的流动性假设：方向保守（默认）或触板无成交（压力）。 |
| `participation_rate` | 本账户在同一 Bar 可模拟成交量占规范成交量的比例，多策略共享。 |
| 影子模式 | 真实行情 + 策略 + 共享内核 + 模拟撮合，记录假设成交以对照真实成交。 |
| 实验快照 / `run_manifest.json` | 锁定数据、代码、规则、配置、依赖与种子的不可变清单。 |
| `journal_seq` | 交易事件库的递增序号；快照保存对应游标，恢复从游标重放。 |
| `SessionClosed` / `SettlementReady` / `TradingDayAdvanced` | 收盘、结算就绪、交易日推进三类日历事件。 |
| `MarketPhase` | 实际合约的交易阶段枚举（竞价申报、竞价撮合、只撤不报、等待连续交易、连续交易、小节休市、停牌、收盘、未知）。 |
