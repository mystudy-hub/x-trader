## 1. 使用说明

每张清单表使用统一列：

| 列 | 含义 |
| :--- | :--- |
| 状态 | `未开始` / `进行中` / `已核验` / `登记缺口` |
| 证据位置 | 归档文件路径、哈希、脱敏联调记录编号或测试编号 |
| 核验日期 | 完成核验的日期（不是网页浏览日期） |
| 负责人 | 姓名或角色 |

原则（来源：规划 §一、§1.2、§二.5）：

- 未核验条目登记为缺口，不作为实盘默认；不因被评审或时间底稿引用就成为生产默认。
- 网页核验日期不等于规则生效日期；缺少一手原文或无法唯一判断适用版本时，登记受影响品种、时段及实验范围，不伪造历史配置。
- 规则来源、核验日期和生效时间分别保存。
- 凭证、终端采集载荷及原始终端标识不得写入本清单或任何归档附件。

<a id="canonical-import-evidence"></a>

规范导入需要三类 JSON 输入；它们是数据与规则的登记，不是要求另写总结。实际路径由 `--catalog`、`--calendar`、`--timings` 指定，文件位于仓库内，导入清单保存其 SHA-256。

| 输入 | 必要结构 |
| :--- | :--- |
| 合约目录 | `schema_version: 1`、`catalog_version`、`entries`。每项包含 exchange、symbol、product、aliases、完整交割年月、multiplier、price_tick、listed_on、last_trading_day、source_id、available_at；不使用年份距离或固定每月 15 日替代目录 |
| 交易日历 | `schema_version: 1`、version、source_id、available_at、coverage_start/end、trading_days、sessions。每个 Session 明确实际合约、交易日、时段标识、起止时间、phase、submit/cancel/match 权限及可获知时间；日期覆盖内未列为交易日的日期不会生成交易时段 |
| 来源时间信息 | `schema_version: 1`、`bar_timings`、可选 `settlement_publications`。Bar 键为原日线日期，或规范 UTC 的分钟结束时间；值明确 trading_day、bar_start/end、open_time、available_at、session_id、includes_auction、evidence_ref。只有明确 open_available_at 和 price_types 时才派生开盘执行参考，无法确认的时间假设须填写 time_assumption |
| 结算发布时间 | `settlement_publications` 按交易日登记 published_at、available_at、is_final 和 evidence_ref；前结算价只保留来源实际提供的字段，不跨缺失日期用上一条记录替代 |

具体解析入口为 `ContractResolver.from_file`、`TradingCalendar.from_file` 和 `load_import_metadata`；单元测试中的合成目录只演示格式，不可直接当成真实规则。批次任何必需字段、目录、边界或结算证据校验失败，都不会提交规范数据清单。

不要求现在先交付完整研究数据集。当前框架和研究原型可用合成证据验证；真实文件接入、规则适用性和阶段出口在材料齐备后验收。
