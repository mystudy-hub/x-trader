## 维护与校验

`docs/requirements.json` 是需求元信息及关联的唯一维护入口。业务正文仍人工维护；带 GENERATED 标记的表格及 02 需求元信息由 `scripts/check_docs.py` 生成。

```text
python scripts/check_docs.py --write
python scripts/check_docs.py --check
```

校验覆盖：编号唯一、来源锚点、正式需求的 R 关联、验收孤立项、待确认议题隔离、阶段与优先级、派生表一致性，以及原始案例、阶段任务、脚本职责、五级门槛、SQL 和目录路径保留。

`tests/fixtures/` 提供 4 份 JSON、15 个固定规格场景，覆盖两种盈亏、手续费、订单回报、撤单边界与价格类型校验。它们均为未执行规格，不属于已通过的 A 系列测试，也不替代真实公告和柜台证据。

本轮已执行生成与只读校验，结果为：108 条 R、104 条正式需求、9 条待确认需求、202 条验收关联、4 份规格夹具通过结构与一致性检查。36 条原始验收行、8 个阶段的任务/交付、21 个脚本职责、5 级门槛、SQL 及原目录路径保留；来源规划哈希一致。

另以仅在内存中修改的数据验证校验器：缺失 R 关联、待确认项进入正式交付、未知验收编号、重复 R 编号、篡改原始通过条件这五种反例均被拒绝；派生表漂移可被检测并按清单恢复。跨日盈亏与手续费夹具的独立算式核对通过。

这些结果仅证明文档、追溯与规格数据的检查已完成，未执行交易内核 A 系列测试或柜台联调；夹具状态仍为 not_executed。
