## 目的与读者

本文从产品视角回答"这个工具给谁用、以什么形态用、每种模式允许什么、禁止什么、优先做什么"。它把规划中散落于各章的运行模式、脚本、报告与门禁整理为矩阵，并列出需要项目发起人拍板的产品决策。读者为项目发起人、策略研究者与开发负责人。凡规划标注"须核验"的交易所 / 柜台事实，本文不作为既定能力陈述。

## 1. 用户角色与核心诉求

| 角色（推断，见 01 §3） | 核心诉求 | 产品必须提供 | 产品明确不承诺 |
| :--- | :--- | :--- | :--- |
| 策略研究者 | 快速筛参数；在实际合约上得到可信的扣费权益曲线；不被未来信息误导 | 向量化通道、事件驱动回测、`available_at` 门禁、执行时点配置、敏感性报告（FR-VAL-01—04、FR-EXEC-02） | 用主连数据得出可对账的资金结果（来源：规划 §2.3、§4.3.2） |
| 交易执行负责人 | 实盘与回测同一套账本；断线、乱序、未知订单不导致重复下单；随时能人工接管 | 唯一执行服务、控制代次、三态发送、恢复对账、人工命令（FR-RISK-07—09、FR-ORD-06—07、FR-REC-04） | 发出清仓请求等于仓位归零；心跳超时自动获得交易权（来源：规划 §4.5.3、§4.5.5） |
| 运维 | 数据不静默丢失；数据库可备份可恢复；有指标和告警 | 分段录制与原子发布、SQLite 备份接口、指标清单、开盘检查脚本（FR-DATA-04、FR-DATA-07、FR-OPS-03） | 分段周期直接等于最大数据损失时间（来源：规划 §5.1） |
| 风控 / 审计 | 每笔规则有来源与生效时间；每次实验可重放；结算单逐项对得上 | 规则来源登记、实验快照、结算单解析器、验收证据分类（FR-RULE-04、FR-VAL-07、FR-LED-08） | 第三方汇总页替代原公告（来源：规划 §2.5） |

## 2. 产品形态

首版是一组 CLI 脚本加一个 Python 包，没有 GUI（来源：规划 §1 末段、§7、§8.1）。按用途分五组：

| 分组 | 脚本 | 职责摘要（来源：规划 §8.1） |
| :--- | :--- | :--- |
| 数据 | `download_data.py`、`compact_ticks.py`、`validate_data.py`、`gaps.py` | 按实际合约下载并记录覆盖；从已发布分段生成规范版本；校验 Schema / 时间 / 结算 / 执行价格覆盖；按日历识别缺口 |
| 研究 | `scan_params.py`、`snapshot.py`、`report.py` | 向量化参数扫描；生成并校验实验清单；输出 HTML 报告 |
| 回测与回放 | `run_backtest.py`、`replay_market_data.py`、`replay_events.py`、`smoke.py` | 共享内核回测；历史行情驱动全链路回放；从游标重放交易事件验证恢复；固定小样本冒烟 |
| 实盘控制 | `run_execution_service.py`、`run_shadow.py`、`watchdog.py`、`control.py`、`preopen_check.py`、`shadow_report.py` | 唯一交易出口；影子模式与最小手数并行；心跳监控与接管；人工暂停 / 撤单 / 减仓 / 恢复；开盘前检查；执行偏差周报 |
| 运维 | `init_env.py`、`reconcile.py`、`parse_statement.py`、`backup_state.py` | 环境与依赖边界验证；差异报告与修复审计；结算单解析比对；一致性备份 |

GUI、遗传编程、低延迟优化在交易与数据基础验收后按需扩展，不占首个可对账闭环的关键路径（来源：规划 §3.3、§9.1 末段）。

## 3. 运行模式矩阵

### 3.1 核算模式（正交于运行模式）

| 模式 | 缺失费率 / 保证金 / 结算价 / 时段时 | 输出标注 | 适用 | 来源 |
| :--- | :--- | :--- | :--- | :--- |
| 研究模式 | 使用第二章第 6 项显式假设（滑点、手续费加收比例、保证金缓冲、参与率）并继续运行 | 报告列出全部假设及影响 | 因子粗筛、参数扫描、早期回测 | 规划 §2.3、§2.6 |
| 精确核算模式 | 中止并说明缺项 | 可与实盘对账的资金结果 | 验收样本、模拟盘、实盘 | 规划 §2.3、§4.4.2 |

两种模式下都不允许：静默借用其他时段 Open / Close 或插值补造成交价（FR-EXEC-03）。进入模拟盘前，研究假设必须以能力表与期货公司实际费率替换（来源：规划 §2.6）。

### 3.2 研究通道

| 通道 | 数据基础 | 成本 | 输出 | 禁止 | 来源 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 向量化通道 | 按当时可见映射拼接的实际合约序列 | 研究模式保守假设 | 候选参数集、敏感性摘要 | 作为成交、资金、风控评估依据 | 规划 §3.3、§8.1 `scan_params.py` |
| 事件驱动通道 | 实际合约 Bar + ExecutionReference | 版本化规则或研究假设 | 订单、成交、账本、风险事件 | 读取 `available_at > 当前策略时钟` 的数据 | 规划 §3.4、§6.1 |

两通道共用数据映射、执行时点、价格来源与成本口径（FR-VAL-04）。【评审补充，PROP-05】建议先比较信号、映射、执行时点与成本输入；相同成交/风控假设下比较规范结果与声明容差，不同假设下逐项归因。状态：待确认。

### 3.3 运行模式

| 模式 | 输入 | 执行端口 | 状态存储 | 输出 | 允许的假设 | 禁止事项 | 来源 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| 回测 | 版本化历史 Bar（/Tick）、规则、日历、初始资金 | `SimulatedGateway` | 内存 Journal，结束时导出规范事件 | 权益曲线、订单 / 成交 / 账本、`run_manifest.json`、报告 | 滑点跳数、参与率、`limit_liquidity_scenario`、延迟分布（均入清单） | 同 Bar 追单；按收益择优互斥顺序；用连续交易 Open 冒充竞价成交 | 规划 §3.4、§5.5、§6.1 |
| 行情回放（`replay_market_data.py`） | 固定版本历史 Bar / Tick + 虚拟时钟 + 可注入故障 | `SimulatedGateway`（强制） | 隔离存储 | 完整事件与差异报告 | 与回测相同 | 加载实盘凭证；向真实端口发送；倍速改变事件顺序 | 规划 §6.6 |
| 事件回放（`replay_events.py`） | 快照游标 + 已有规范事件 + 故障情景 | 无（重放事实） | 隔离存储 | 订单 / 预占 / 账本差异 | 无 | 混入实盘统计 | 规划 §6.6、§8.1 |
| 影子模式 | 真实 CTP 行情 | `SimulatedGateway` | `live/trading.db`（隔离账户视图） | 假设成交记录、周报 | 撮合与排队假设 | 计入实测滑点统计 | 规划 §6.5 |
| 模拟盘（仿真柜台） | 真实 / 仿真行情 | CTP 适配器 → 仿真柜台 | `live/trading.db` | 联调证据、运行时长与场景报告 | 仿真撮合与实盘不同，仅证接口与流程 | 以仿真通过证明真实时段、费率、风控已验证 | 规划 §2.2、§9.1 阶段 5 |
| 最小手数实盘 | 真实行情 | 唯一执行服务 → 真实 CTP | `live/trading.db` | 真实成交、与影子的关联比对、结算单对账 | 无 | 用最小手数成交证明更大容量 | 规划 §6.5、§9.3 |
| 生产 | 真实行情 | 唯一执行服务 → 真实 CTP | `live/trading.db` + 备份 | 同上 + 每日对账 | 无 | 未核验能力作为默认 | 规划 §9.3 |

所有含真实交易连接的模式均受同一规则：结算未完成、对账差异、无法持久化、队列溢出、行情过期时禁止新增风险，但回报处理、对账、告警与保守风险评估继续运行（FR-CAL-12、FR-OPS-03）。

## 8. 与参考架构及常见开源框架的差异

| 常见做法 | 本项目做法 | 来源 |
| :--- | :--- | :--- |
| 主连 / 连续合约直接回测成交 | 连续序列只算信号；成交、费用、保证金、涨跌停用实际合约原始价格 | 规划 §4.3.2 |
| 回测与实盘各一套持仓 / 资金算法 | 共享领域内核，`BaseEngine` 只组织运行 | 规划 §3.4 |
| `OrderRef` 作为订单唯一键 | 跨会话不能单独作键；成交先于报单回报时用已核验 `ExchangeID + OrderSysID` 或原会话映射；无法归属的成交存为待关联占位 | 规划 §4.1.3 |
| `YdPosition` 直接当昨仓余量 | 先核验是日初量还是剩余量；SHFE / INE 分条记录按实际口径归一化 | 规划 §4.1.1 |
| `ReqOrderInsert` 返回 0 视为已报 | 仅为 `SENT_UNKNOWN`，等待远端确认证据 | 规划 §4.1.4 |
| 超时即拒单并重发 | 超时只升级核对与告警，禁止盲目重发 | 规划 §4.1.4、A03 |
| 统一 15:00 收盘、日期加一天算交易日 | 版本化 Sessions 与期货日历；`SessionClosed` 按合约时段 | 规划 §4.2 |
| 撤单请求成功即视为已撤 | 撤单到达不等于生效；拒绝撤单保留原单与预占 | 规划 §4.1.2、§6.3 |
| 移仓固定扣双倍手续费加滑点 | 损益来自真实两腿成交；价差不入账本 | 规划 §4.3.4 |
| 进程内止损当作托管保护 | 未核验时按无托管保护设计；独立看门狗与外部存活告警 | 规划 §4.5.5 |
| 限价触及即全部成交 | 触价仅说明价格到达；参与率预算、涨跌停情景、部分成交 | 规划 §6.1 |
| 两 Tick 表示固定延迟 | 基于时间的独立延迟事件，稀疏行情下定时器仍推进 | 规划 §6.3 |
| DuckDB 通配读取数据目录 | 从 manifest 取文件列表，禁止多版本通配 | 规划 §5.3 |
| 单一账本 | 一套事实、两种盈亏视图（盯市 / 逐笔），权益只增加一次 | 规划 §4.4.1 |

## 9. 产品风险与假设

| 风险 | 影响 | 规划中的缓解 | 残余风险 |
