## 一、阻塞项（必须修复后才能重新申请 S3 出口）

### B1. 向量化通道存在前视偏差，与事件驱动通道执行时点不一致

`qh_trader/research/vector_backtest.py:74-108`。信号由 `closes[i]` 计算得到后，`pos` 立即更新，随后第 106 行用**同一根 Bar** 的 `closes[i] - closes[i-1]` 乘以新 `pos` 计入权益。即在 Bar i 收盘看到信号，却赚到了 Bar i-1→i 的涨跌。

复现（固定种子随机游走 300 根，fast=5, slow=20，零手续费）：

| 口径 | 总盈亏 |
| :--- | ---: |
| 现实现 | +600 |
| 手工"同 Bar 前视" | +600 |
| 手工"次 Bar 生效"（正确） | -300 |

违反 FR-MATCH-01 因果约束与 FR-VAL-04 "两条通道共用执行时点及价格来源"。事件驱动通道是下一 Bar **开盘**成交，向量化通道是当根 Bar **收盘**成交且吃当根收益，两者不可能对齐。`scan_params.py` 当前输出的全部排名无效。

修复：持仓生效移到 i+1，执行价用 `open[i+1]`（与 SimulatedGateway 开盘撮合一致），并补一条"同一 Bar 序列、同参数、零滑点零参与率约束下两通道成交序列一致"的容差测试（对应 06 中待确认的 FR-VAL-08）。

### B2. 网关的 ACCEPTED / CANCELLED 回报从未送达领域内核，撤单不释放预占

`gateway/simulated_gateway.py:187-196, 246-255` 把接受与撤单回报放入 `self._events`；`engine/backtest_engine.py:145-150` 只消费 `match_bar()` 返回的切片；`drain_events()` 在整个仓库无调用方。

复现（4 根 Bar，Bar 1 发限价 2000 买单，Bar 2 撤单）：

```
OrderManager: ord-1 status=CREATED send_state=SENT_UNKNOWN   # 网关内部已 CANCELLED
ledger._funds_reservations = {'ord-1': margin=2000.0, fee=5.0}  # 永不释放
```

正常成交路径同样跳过 ACCEPTED，订单从 CREATED 直接变 FILLED。后果：

- 撤单后资金预占与平仓持仓预占永久冻结，`available_for_new_trades` 被错误压低，长回测会出现"资金不足"假象。
- 回测结束时未成交订单状态与预占全部残留，账本不可对账（S3 出口要求"账务可对账"）。
- A25-04 / FR-MATCH-07 "撤单被拒原单与预占保留、成交只入账一次"没有任何实现基础。
- `cancel()` 第 233 行用 `datetime.now(timezone.utc)` 作为 `event_time`，墙钟进入回测事件流，破坏 A15 / A28 确定性。

修复：网关不再自持事件队列，`submit()` / `cancel()` 返回的回报由引擎在同一虚拟时刻（`self.now()`）经 `process_order_event` 入内核；撤单确认时调用 `ledger.release_funds` 与 `position_manager.release_reservation`（S2 已提供）。撤单时间必须来自虚拟时钟并经 FR-MATCH-07 到达延迟建模。

### B3. 开盘候选成交被随后的收盘触板否定（A20 核心断言反了）

`gateway/simulated_gateway.py:319-330`：`is_upper` / `is_lower` 以 `bar.close` 判定，然后同时作用于"阶段一开盘撮合"与"阶段二盘中撮合"。

复现：已生效市价买单，Bar open=3000（未触板）、close=3100=涨停价 → **无成交**。

规格 FR-MATCH-02、FR-MATCH-03、05 §17 三处明文："开盘候选不能因随后收盘触板而被否定"、"不能根据后来的完整 Bar 分类撤销此前已确定的成交"。A20 验收条件正是"仅改变后来收盘是否触板，既有开盘成交必须不变"。`test_a20_limit_scenario_touch_no_fill` 只构造了 open 已在涨停的样本，所以没有暴露。

修复：开盘阶段只用 `bar.open` 对比涨跌停；盘中阶段再用 `bar.close`（或 high/low 触及边界）判定。测试补 A20 成对样本：同一开盘输入，收盘触板 / 不触板，断言开盘成交完全相同。

### B4. run_manifest（S3-05 / FR-VAL-07）远未满足要求，且覆盖写入

`scripts/run_backtest.py:106-140`。缺：依赖版本、数据文件内容哈希（`data/snapshots.py` 的 `DataSnapshot` 已存在但未接入）、Sessions 与规则版本、执行策略与数据来源、延迟参数、事件优先级、随机种子、样本划分、**订单 / 成交 / 账本规范化输出哈希**。没有输出哈希，A15 "重复运行哈希一致"无法验收。

另外：`created_at` 用墙钟；固定写 `runs/backtest/run_manifest.json` 每次覆盖，违反"变更应生成新的实验标识，不能覆盖旧结果"；`snapshot_id` 未传时兜底写死 `canonical-2024v1`，与实际读取不符。WBS 要求的 `data/snapshots.py` 扩展与 `scripts/snapshot.py` 未做。

### B5. S3-01、S3-09、S3-10 未实做，实现记录不实

- **S3-01**：`core/clock.py`、`core/event.py` 未改动；引擎未使用 `EventQueue`，同时间事件优先级策略未接入；无 `TimerEvent` 调度，"空行情时段定时器仍运行"（A28、F18）无实现。
- **S3-09**：`data/replay.py` 未改动；`scripts/replay_market_data.py` 是 `run_backtest.py` 的复制，无单步 / 原速 / 加速 / 尽快模式，无倍速一致性对照，无独立手工预期。绕过 `HistoricalMarketDataAdapter` 直接 `storage.read_bars`，`available_at` 可见性约束未生效。`test_a28_full_pipeline_replay_idempotency` 只做两次运行互比，FR-VAL-06 硬约束明文禁止以此代替独立预期。
- **S3-10**：`tests/fixtures/sessions/` 不存在；`grep` 网关与引擎无任何 `MarketPhase`、`can_match`、`sessions()` 引用。测试文件名含 A25 但没有一条 A25 测试。
- 06 实现记录称"完成 S3 全部 11 个工作项"、"新增 14 项端到端测试、564 项通过"。实际新增 5 个测试文件 15 个用例，当前全量 570；数字本身不重要，但"全部完成"与"A25 规则边界接入"的表述需要撤回。

## 二、主要缺陷（出口前应修复）

### M1. 撮合价格未受 Bar 高低价与价格步长约束

`simulated_gateway.py:363-393`。市价买单 5 跳滑点、Bar high=3000 → 成交价 3005，超出该 Bar 实际价格域。`limit_price_ticks * price_tick` 后加滑点未按步长对齐。FR-MATCH-04："成交价始终满足订单限价、价格步长和涨跌停约束"。修复：成交价 clamp 到 `[bar.low, bar.high]` 与涨跌停边界，并对齐 `price_tick`。

### M2. 订单永不过期，跨交易日无限存活

网关无有效期概念。复现：9 月 10 日的限价单在 9 月 20 日的 Bar 成交，`Trade.trading_day` 记为撮合日。`test_a11_zero_volume_and_causality` 把 Bar 1 信号在 Bar 3 成交当作正确行为固化。CTP 默认 GFD 当日有效；跨日残留只限夜盘→日盘（A25-02）。回测与实盘订单生命周期口径不一致，属于 FR-MATCH-01 "回测与实盘同一实现"范畴。修复：跨交易日结算时按有效期规则将未成交单置 EXPIRED，并释放预占（依赖 B2）。

### M3. 盘中撮合使用了订单到达前的价格路径

`simulated_gateway.py:399-436`：阶段二对所有活跃订单用整根 Bar 的 high/low 撮合，不检查 `created_at` 是否早于 `bar_start`。复现：`created_at` 在 Bar 中段的限价单按整根 Bar 的 low 成交，`event_time=bar_end`。05 §17："若订单在 Bar 内才生效而没有更细数据，保守模式延至下一完整 Bar 评估"。当前引擎不会产生此类订单，但网关是共享组件且 A25-04 延迟撤单场景必然产生盘中到达。

### M4. 参与率预算的"至少 1 手"分支把保守约束改成乐观

`simulated_gateway.py:312-314`。rate=0.001、volume=50 仍成交 1 手，预算应为 0。FR-MATCH-04 禁止超出预算。删除该分支。

### M5. BaseEngine 硬编码经济参数，多品种与规则缺失时错误

`engine/base_engine.py`：
- 第 223~225 行资金预占兜底价 3000；`limit_price_ticks` 直接当价格用（未乘 `price_tick`），限价 3000 跳 × 0.5 元步长的品种会预占 2 倍保证金。
- `contract_multiplier` / `commission_per_lot` / `margin_ratio` 为引擎级单值，多品种回测（S4 已在用）必然错。
- 第 286~300 行 `commission_rule` 查询失败 `except Exception` 静默回退固定费率，违反"缺规则明确失败"（FR-RULE、A21 "不静默回退"）。
- 第 181 行 `strategy_id="strategy"` 硬编码，多策略共享预算与归因无法区分。
- `journal` 注入后从未 `append`，S2-11 "回测结束导出规范事件"未做。

### M6. 跨日结算价只取最后一根 Bar 的合约

`backtest_engine.py:128-135, 179-189`。`settle_day({last_bar.instrument: last_bar.close})` 只给一个合约结算价，多品种时其余持仓无结算价；末尾 `settle_day` 异常被吞为 warning，账本可能停在未结算状态而 `final_equity` 照常输出。跨日检测用 `bar.meta.trading_day` 大小比较而非日历 / 结算事件（FR-CAL-04/05 S3 范围）。

### M7. 绩效指标（FR-VAL-03 / S3-06）缺项且口径不一

`analysis/performance.py`：
- 缺保证金峰值、未成交 / 拒单统计、数据降级、月度收益、持仓时长、样本覆盖周期，报告未注明收益频率 / 年化因子 / 无风险假设。
- 第 147~148 行年化收益 = 总收益 × (242 / Bar 数)，Bar 数按快照条数而非交易日；1h Bar 会把年化缩小约 4~6 倍，夏普同样失真。
- 胜率 / 盈亏比在 `_compute_paired_trade_pnls` 里用固定 `commission_per_lot=5` 重算手续费，与账本实际扣费（可能来自 `commission_rule`）是两套口径；应从账本的逐笔平仓事实取值。
- `visualizer.py` 只有文本摘要，没有权益曲线输出；S3 出口要求"扣费权益曲线"。

### M8. 敏感性分析（S3-07 / FR-VAL-02）与样本划分实际未交付

`scan_params.py` 只是双均线参数网格，没有手续费 / 滑点 / 参与率 / 触价情景的试验矩阵，也没有"保存试验数量与失败结果"。`analysis/validation.py:19` 的 `SampleSplit` 继承 `Sequence` 却未实现 `__len__` / `__getitem__`，实例化即 `TypeError`（死代码但已导出）。`walk_forward_slices` 无 purge / embargo。

### M9. 风控流水线与 Sessions 权限未接入引擎

`send_order` 直接进 SmartRouter 与预占，S2-06 `domain/risk.py` 未调用，FR-RISK-03 "回测中生效并在报告可见"（A19）为零。无 FR-CAL-07 报撤权限与 `can_match()` 检查（见 B5 S3-10）。配置模板中声明的 `execution_strategy` / `missed_execution` 无任何代码读取。
