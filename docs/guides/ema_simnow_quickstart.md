# EMA 策略验证与 SimNow 起步

本轮先交付代码和仿真接入准备。首轮配置为 **SHFE 螺纹钢实际合约、30 分钟同周期 EMA200、A/B 独立比较、最多 1 手、单笔止损距离对应的风险预算不超过权益的 1.5%**。2026-09-28 的柜台预检选出 `SHFE.rb2701`；后续运行应重新预检，不能永久固定“主力”合约。

## 策略口径

参数位于 `config/strategy_validation.yaml`，实现位于 `qh_trader/strategy/examples/ema_trend.py`。

- EMA20/50/200、ATR14；按完整且已可见的 30m Bar 更新指标。
- 模式 A：趋势侧回踩均线后，阳线收盘突破前一根高点做多；做空反向。
- 模式 B：EMA20/50 在 EMA200 趋势侧交叉，同时突破此前 N 根高低点；不包含信号 Bar 本身。
- EMA200 斜率、近均线反复穿越过滤震荡。连续确认 2 根、突破窗口 20、结构窗口 5、回踩容差 0.25ATR 等是首轮定量参数，尚未经优化。
- 初始止损在实际成交后建立；ATR 与结构距离取更紧者。盈利达到 2ATR 后保本，并按极值回撤 2ATR 跟踪。实盘行情路径以新鲜 Tick 触发保护；EMA50 破位按已闭合 Bar 决策。
- 止损触发后提交限价退出意图，不承诺止损价成交。首版没有未成交止损单的自动撤换追价，需要有人值守。跳空、交易所限制和滑点可能使实际亏损超过初始风险预算。
- Bar 回测无法重建 Tick 的高低先后，使用当时已有止损、在观察成立后下一可执行价退出。回测报告明确记录该差异，不借 Bar 高低推定有利成交。

## 1. 检查数据，分别验证 A/B

```powershell
& .\.venv\Scripts\python.exe scripts/validate_strategy.py --config config/strategy_validation.yaml --symbol SHFE.rb2701
```

在配置中补入同一实际合约的数据快照、合约目录、版本化日历与来源时间元数据，并在查看策略结果前固定 `research.split_date`。样本外仅使用其开始前已可见的数据预热。预热数按策略配置计算，EMA200 至少需要 200 根，斜率和形态确认还需要额外历史。

实时启动须取得最近完整的预热窗口；其中任何一根尚未可见都阻断启动，不能跳过迟到 Bar、从更早历史补足数量。

## 3. 观察行情

```powershell
& .\.venv\Scripts\python.exe scripts/run_simnow_strategy.py --preflight runs/s0/simnow_preflight_current/preflight.json --mode observe --entry-mode A --seconds 60 --out runs/live/ema_observe
```

默认是 `observe`，只接行情，不建立下单通道。缺少当前日历时仍可记录 Tick，但输出明确的 `bar_blocker`；加 `--calendar <当前合约日历.json>` 后才能按登记 Sessions 聚合 Bar。每个连续交易小节独立分桶，首个残桶、超时或断线受损桶舍弃；该规则不能直接假定与其他供应商的“30 分钟”口径一致。

输出包括 `runtime.json`、`ticks.jsonl`、`bars.jsonl` 和 `strategy_events.jsonl`。这是本次运行的诊断采样，不替代 S7 的完整 Tick 存储系统。7×24 环境可能返回历史镜像，旧行情不能作为当前策略输入。

## 4. 仿真交易的启动条件

准备完整后再使用 `--mode trade`，A/B 分开运行并使用各自实验记录。入口必须检查：

1. 新鲜且与本机账号一致的 SimNow 预检、已核对的实际合约和交易日。
2. 合格的 30m 预热数据、当前会话日历；不在登记交易时段时不放行。
3. 平今/平昨映射及证据、可表达且唯一匹配合约的费用/保证金参数。
4. 空仓且无活动委托的首轮账户；已有状态必须先按恢复流程核对，不能换输出目录绕过唯一执行服务。
5. 旧出口已隔离的明确确认，随后按“提升代次 → 对账 → 放行”运行。

策略只写 SQLite 命令表，唯一执行服务负责风控、记账及调用柜台。断线、行情质量异常、未完成策略处理或状态不一致时停止新命令。到期退出若仍有持仓、活动委托或未处理命令，结果标记需要人工接管，不自动宣称完成。

正常休市不计入五秒行情超时；启动和复市后五秒仍无新行情会暂停。无论定时检查还是新 Tick 检出受损 Bar，都先暂停再阻断策略输入。运行入口先处理已提交回报与行情，质量和时效检查完成后再处理策略命令；失去就绪时遗留的本地待发送命令须核对后处置。
